第18章 多线程服务器端的实现

发表于2026-07-15|更新于2026-07-16|TCP-IP网络编程
|字数总计:2.9k|阅读时长:11分钟|阅读量:

总结

小结:: 本章介绍如何使用线程替代进程来构建并发服务器。核心在于理解线程的轻量级特性（共享地址空间、快速创建/切换），以及使用互斥锁和信号量解决线程同步问题。多线程是实现高性能并发服务器的关键技术。

从多进程到多线程

多进程的缺点

在第10章中我们使用多进程实现了并发服务器，但多进程存在以下问题：

问题 说明
高内存占用 每个进程拥有独立的地址空间（4GB 虚拟内存），即使写时复制也开销不小
上下文切换慢 进程切换涉及页表切换、TLB 刷新等，开销大
IPC 复杂 进程间通信需要管道、消息队列、共享内存等特殊机制
可扩展性差 随着连接数增加，进程数线性增长，系统资源迅速耗尽

线程的优势

线程是轻量级的进程，同一个进程内的线程：

  • 共享地址空间：所有线程共享代码段、数据段、堆（但各有独立的栈）
  • 创建/销毁开销小：不需要复制地址空间
  • 通信简单：直接通过全局变量即可通信（但需注意同步问题）
  • 切换速度快：同一进程内的线程切换比进程切换快得多

进程 vs 线程对比

对比项 进程 线程
地址空间 独立 共享
数据保护 天然隔离，互不影响 需要同步机制保护共享数据
创建速度 慢（复制地址空间） 快
切换速度 慢（页表切换） 快
IPC 需要特殊机制 直接共享变量
多核利用 ✅ 每个进程可在不同核运行 ✅ 每个线程可在不同核运行
编程复杂度 相对简单（隔离性好） 需要处理同步问题

线程的创建与运行

POSIX 线程（pthread）

Linux 环境使用 POSIX 线程标准，头文件 <pthread.h>，链接时需要 -lpthread。

线程的创建：pthread_create()

参数 说明
thread 用于保存线程 ID
attr 线程属性（传 NULL 使用默认属性）
start_routine 线程入口函数（返回 void*，参数 void*）
arg 传给线程入口函数的参数

等待线程结束：pthread_join()

  • 功能：等待指定线程终止，类似进程的 waitpid()
  • 注意：如果不 pthread_join，主线程退出后，进程内所有线程都会立即终止

⚠️ 使用互斥锁的要点： 1. 临界区（需要保护的区域）越小越好，只在必要时加锁，避免锁住无关系代码降低性能 2. 小心死锁：两个线程各自持有一把锁，同时等待对方释放 3. 加锁和解锁必须成对出现，任何路径都要保证解锁

信号量（Semaphore）

信号量通过计数器来控制对共享资源的访问数量。POSIX 信号量有两种：有名信号量（文件系统可见）和无名信号量（内存中）。

多线程并发回声服务器

服务器端实现

关键点解析

技术点 说明
动态分配客户端套接字 每个 accept 返回的 clnt_sock 用 malloc 动态分配，避免局部变量被覆盖
全局客户端列表 使用数组存储所有客户端套接字，用互斥锁保护
pthread_detach 分离线程，线程结束后自动释放资源，不需要 pthread_join
send_msg 广播 向所有连接的客户端发送消息

线程存在的问题与解决方案

线程安全问题

多个线程同时访问共享数据时，需要使用同步机制保护。常见问题：

问题 描述 解决方案
竞态条件 多个线程同时读写同一变量 互斥锁
死锁 两个线程互相等待对方释放锁 固定加锁顺序 / 超时
数据竞争 未同步访问共享内存 互斥锁 / 原子操作
伪共享 不同线程的变量在同一缓存行 缓存行对齐

内存管理

线程池

如果每个客户端都创建一个新线程，大量连接时线程数会暴涨。更好的方案是使用线程池：

线程池的优势： - 避免频繁创建/销毁线程的开销 - 控制并发线程数，防止系统过载 - 任务排队，公平调度

本章要点

函数/概念 说明
pthread_create() 创建线程
pthread_join() 等待线程结束并获取返回值
pthread_detach() 分离线程，自动释放资源
pthread_mutex_lock/unlock 互斥锁保护临界区
sem_init/wait/post 信号量控制执行顺序或资源数量
竞态条件 多线程访问共享数据时的问题
临界区 需要互斥保护的代码段
线程池 固定数量的线程处理任务队列

灵魂总结

多线程是构建高性能并发服务器的关键技术。与多进程相比，线程轻量、通信简单、切换快速。但要特别注意同步问题——互斥锁保护共享数据，信号量控制执行顺序。

黄金法则：能用锁保护临界区，但不能滥用锁。临界区越小，并发性能越高。先保证正确性，再优化性能。🔒
