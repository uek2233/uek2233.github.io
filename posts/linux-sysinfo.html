Linux 应用编程：系统信息与资源

系统信息与资源

学习 Linux 应用编程时整理的笔记，涵盖：系统信息获取（uname/sysinfo/sysconf）、时间与时钟、进程时间、随机数、休眠、堆内存分配与内存对齐、proc 文件系统。

阅读建议：先搞清楚「系统是什么」（系统信息），再知道「现在几点」（时间），接着看「程序跑了多久」（进程时间），然后是「随机与等待」（随机数 / 休眠），最后掌握「内存怎么拿」（堆内存 / 对齐）与「内核怎么问」（proc 文件系统）。

系统信息

Linux 提供了几个系统调用 / C 库函数用于获取系统信息：操作系统名称、内核版本、主机名、硬件架构，以及各种运行时可配置的限额（页面大小、CPU 数量、节拍率等）。命令行中对应的查看工具是 uname -a、hostname 等。

函数 作用 成功返回 失败返回
uname() 获取操作系统名称、主机名、内核版本、硬件架构等 0 -1
sysinfo() 获取系统总体信息（运行时间、内存、负载、进程数等） 0 -1
gethostname() 获取主机名 0 -1
sysconf() 获取运行时系统限制 / 配置值（页面大小、CPU 数、节拍率等） 配置值 -1

uname() — 获取系统基本信息

作用:: 将操作系统名称、主机名、内核发行版本、内核版本、硬件架构等系统信息填入 struct utsname 结构体。uname -a 命令内部就是调用它。

用法：

  • buf：指向 struct utsname 的指针，函数将信息写入其中

注意事项：

  1. uname() 与 uname 命令的选项对应关系：-s→sysname、-n→nodename、-r→release、-v→version、-m→machine
  2. nodename 通常与 gethostname() 得到的主机名一致
  3. struct utsname 中的数组长度由实现定义（Linux 上各字段为 65 字节），不可假设固定值

sysinfo() — 获取系统总体信息

作用:: 获取系统运行时间、平均负载、内存使用情况、进程数等总体信息，填入 struct sysinfo 结构体。比逐一读取 /proc/meminfo、/proc/loadavg 更方便。

用法：

  • info：指向 struct sysinfo 的指针，函数将信息写入其中

注意事项：

  1. loads[] 不是浮点数：它是整数，需要除以 65536.0 才是熟悉的负载值（如 1.5）
  2. 内存字段单位是字节：字段值与 mem_unit 的乘积才是真实字节数（Linux 上 mem_unit 通常为 1）
  3. freeram 是"完全空闲"的内存，实际可用内存还要算上 buffer/cache，判断系统内存是否够用建议看 /proc/meminfo 中的 MemAvailable 字段
  4. uptime 与 cat /proc/uptime 的第一个数字一致

gethostname() — 获取主机名

作用:: 获取当前系统的主机名，写入调用者提供的缓冲区。对应 hostname 命令。

用法：

  • name：存放主机名的缓冲区
  • len：缓冲区 name 的大小（字节）

注意事项：

  1. Linux 上主机名最大长度为 HOST_NAME_MAX（64 字节，含 '\0'），缓冲区给 64 字节以上即可
  2. Linux 上若 len 太小，函数会返回 -1 并设置 errno = ENAMETOOLONG（POSIX 允许静默截断，但 Linux 不会）
  3. 结果不保证以 '\0' 结尾（若缓冲区刚好装满），保险起见可手动 name[len-1] = '\0'
  4. 与 uname() 的 nodename 字段含义相同

作用:: 在运行时查询系统的各种限制和配置值，如页面大小、在线 CPU 数量、时钟节拍率、可打开文件描述符上限等。编译期已知的常量可用宏（如 PAGE_SIZE），但运行时值一律用 sysconf() 获取，保证可移植性。

用法：

常用 name 参数：

name 参数 含义
_SC_PAGESIZE 内存页面大小（字节），如 4096
_SC_NPROCESSORS_ONLN 当前在线的 CPU 数量
_SC_NPROCESSORS_CONF 系统配置的 CPU 数量

  2. 判断失败前先清空 errno：errno = 0; v = sysconf(name); if (v == -1 && errno != 0) { /* 出错 */ }
  3. sysconf(_SC_CLK_TCK) 返回的节拍率是 times() 等函数的换算依据（见「进程时间」章节）
  4. 不要在编译期用 #define PAGE_SIZE 之类的硬编码，不同架构/内核配置可能不同

时间

基本概念

GMT 时间：格林威治标准时间（Greenwich Mean Time），以英国格林威治天文台所在地的平太阳时为基准。 UTC 时间：世界协调时间（Coordinated Universal Time），原子钟基准，与 GMT 在民用上几乎等价，是国际标准时间。命令 date -u 可查看当前的 UTC 时间。

系统时钟 vs 实时时钟（RTC）：

操作系统中一般有两个时钟：

  • 实时时钟（RTC，硬件时钟）：由主板上的电池供电的硬件芯片维护，系统关机后仍在走。
  • 系统时钟（软件时钟）：由内核维护，开机后从 0 开始计数。

Linux 系统开机启动后，会首先读取一次 RTC 获取实时时钟作为系统时钟的初始值，之后内核便开始维护自己的系统时钟。所以 RTC 硬件只在系统开机启动时读取一次，用于对系统时钟进行初始化，之后运行过程中便不再读取它了。hwclock 命令用于查看/设置硬件时钟。

jiffies（系统节拍）：

jiffies 是内核中定义的一个全局变量，内核使用它记录系统从启动以来的节拍数，用来记录以系统节拍时间为单位的时间长度。节拍率（每秒节拍数）就是 HZ，可由 sysconf(_SC_CLK_TCK) 获取（通常为 100）。

当需要获取当前时间点时，可以使用 jiffies 去换算，当然并不需要手动计算——Linux 提供了相应的系统调用 / C 库函数用于获取当前时间，如 time()、gettimeofday()、clock_gettime()，其实质上就是通过 jiffies 换算得到的。

Epoch（日历时间的起点）：1970-01-01 00:00:00 +0000 (UTC)。从该时刻到现在的秒数称为日历时间（calendar time），数据类型为 time_t。

函数 作用 成功返回 失败返回
time() 获取日历时间（秒级） 秒数 (time_t)-1
gettimeofday() 获取日历时间（微秒级） 0 -1
clock_gettime() 获取指定时钟的时间（纳秒级） 0 -1
ctime() / ctime_r() 将 time_t 转为固定格式字符串 字符串指针 NULL
localtime() / localtime_r() 将 time_t 转为本地时间的 struct tm struct tm 指针 NULL
gmtime() / gmtime_r() 将 time_t 转为 UTC 时间的 struct tm struct tm 指针 NULL
asctime() / asctime_r() 将 struct tm 转为固定格式字符串 字符串指针 NULL
strftime() 按自定义格式格式化 struct tm 写入字符数 0
mktime() 将 struct tm 转为 time_t（与 localtime() 相反） 秒数 (time_t)-1
settimeofday() 设置系统本地时间 0 -1

time() — 获取日历时间

作用:: 得到从 1970-01-01 00:00:00 +0000 (UTC)（即 Epoch）到现在所经过的秒数，即日历时间。

用法：

  • tloc：若不为 NULL，函数还会把结果写入 *tloc（可传 NULL 只取返回值）

注意事项：

  1. 精度只有秒级，需要更高精度用 gettimeofday() 或 clock_gettime()
  2. time_t 在 32 位系统上是 32 位有符号整数，2038 年问题（溢出）；64 位系统无此问题

gettimeofday() — 获取日历时间（微秒级）

作用:: 得到从 Epoch 到现在所经过的秒数 + 微秒数，即微秒级的日历时间。结果存入 struct timeval。

用法：

  • tv：存放结果的 struct timeval
  • tz：时区参数，已废弃，一律传 NULL

注意事项：

  1. tz 参数已废弃，传 NULL（历史原因保留签名）
  2. 精度受内核时钟分辨率限制（实际约微秒级，并不保证精确到 1 微秒）
  3. POSIX.1-2008 已将 gettimeofday() 标记为过时（legacy），新代码推荐 clock_gettime()

clock_gettime() — 获取指定时钟时间（纳秒级）⭐ 推荐

作用:: 获取指定时钟（clockid）的当前时间，纳秒级精度，存入 struct timespec。它是现代 Linux 下获取时间最推荐的方式。

用法：

常用 clockid：

clockid 含义
CLOCK_REALTIME 墙上时钟（系统时间），可被 settimeofday() / NTP 修改，可能向前或向后跳变
CLOCK_MONOTONIC 单调时钟，不受系统时间修改影响，适合测量时间间隔
CLOCK_PROCESS_CPUTIME_ID 当前进程消耗的 CPU 时间
CLOCK_THREAD_CPUTIME_ID 当前线程消耗的 CPU 时间

注意事项：

  1. 测量耗时用 CLOCK_MONOTONIC，不要用 CLOCK_REALTIME——系统时间被 NTP 校准或用户修改时，CLOCK_REALTIME 会跳变，导致测出的间隔不准甚至为负
  2. 老系统（glibc < 2.17）编译需链接 -lrt，新系统不需要
  3. 对应设置时间的函数是 clock_settime()（需 root 权限）

ctime() & ctime_r() — 将日历时间转为字符串

作用:: 将 time_t 日历时间转换为固定格式的可打印字符串，格式如：Wed Jun 30 21:49:08 1993\n（带换行符）。

用法：

  • timep：指向 time_t 时间的指针
  • buf：调用者提供的缓冲区，至少 26 字节（含 '\0'）

注意事项：

  1. ctime() 返回指向静态存储区的指针，线程不安全；多线程程序用 ctime_r()
  2. ctime() 等价于 asctime(localtime(timep))——它内部按本地时区转换
  3. 字符串末尾自带 '\n'，打印时不用再换行
  4. 格式固定不可定制，需要自定义格式用 strftime()

localtime() & localtime_r() — 转为本地时间结构体

作用:: 把 time() / gettimeofday() 得到的秒数（time_t 日历时间）变成一个 struct tm 结构体表示的本地时间（受时区 TZ 环境变量和 /etc/localtime 影响）。

用法：

  • timep：指向 time_t 时间的指针
  • result：调用者提供的 struct tm 缓冲区（线程安全版本用）

struct tm 结构体：

注意事项：

  1. localtime() 返回指向静态存储区的指针，线程不安全；多线程用 localtime_r()
  2. tm_year 是实际年份减 1900（如 2026 年 → 126），tm_mon 从 0 开始（0 代表 1 月）——打印时记得 +1900、+1，这是最常见的出错点
  3. 转换时若 timep 对应的时间超出 struct tm 可表示范围，返回 NULL
  4. 第一次调用会读取时区文件，可能较慢；之后有缓存

gmtime() & gmtime_r() — 转为 UTC 时间结构体

作用:: 把 time_t 时间变成一个 struct tm 结构体表示的时间，与 localtime() 不同的是：gmtime() 得到的是 UTC 国际标准时间，并不是计算机的本地时间。

用法：

  • timep：指向 time_t 时间的指针
  • result：调用者提供的 struct tm 缓冲区（线程安全版本用）

注意事项：

  1. 与 localtime() 的唯一区别是时区基准：gmtime() 用 UTC，localtime() 用本地时区
  2. 同样存在线程安全问题，多线程用 gmtime_r()
  3. 北京时间（UTC+8）比 UTC 早 8 小时，gmtime() 得到的小时数比 localtime() 少 8

asctime() & asctime_r() — 将 struct tm 转为字符串

作用:: ctime() 是将 time_t 时间转换为固定格式字符串，而 asctime() 则是将 struct tm 表示的分解时间转换为固定格式的字符串（格式与 ctime() 相同）。

用法：

  • tm：指向 struct tm 分解时间的指针
  • buf：调用者提供的缓冲区，至少 26 字节

注意事项：

  1. 关系：ctime(t) == asctime(localtime(t))——ctime() 内部先 localtime() 再调 asctime()
  2. 同样线程不安全，多线程用 asctime_r()
  3. 该函数已被 POSIX.1-2008 标记为过时，新代码建议直接用 strftime() 定制格式

strftime() — 自定义时间格式

作用:: 根据自己自定义的格式将 struct tm 分解时间格式化为字符串，是格式化时间最灵活、最常用的函数。

用法：

  • s：输出缓冲区
  • max：缓冲区大小（字节）
  • format：格式字符串，% 开头的转换说明会被替换
  • tm：指向 struct tm 分解时间

常用格式说明符：

说明符 含义 示例
%Y 四位年份 2026
%m 月份（01-12） 08
%d 日（01-31） 23
%H 小时（00-23，24 小时制） 14
%M 分钟（00-59） 05
%S 秒（00-59） 09
%A / %a 星期全名 / 缩写 Sunday / Sun
%B / %b 月份全名 / 缩写 August / Aug
%F 等价 %Y-%m-%d 2026-08-23
%T 等价 %H:%M:%S 14:05:09

注意事项：

  1. 返回 0 表示空间不足或出错（注意：格式化结果恰好为空时也会返回 0，需要结合 errno 区分）
  2. 返回的字符数不包含 '\0'
  3. 先 localtime_r() / gmtime_r() 得到 struct tm，再交给 strftime() 格式化

mktime() — 将 struct tm 转为 time_t

作用:: 与 localtime() 相反：mktime() 将使用 struct tm 结构体表示的分解时间转换为 time_t 日历时间（秒数）。同样是一个 C 库函数。

用法：

  • tm：指向 struct tm 分解时间（按本地时区解释），函数会修正其中的 tm_wday、tm_yday 字段

注意事项：

  1. 输入只需设置年、月、日、时、分、秒即可，tm_wday / tm_yday 会被函数自动修正
  2. tm_isdst 要正确设置：大于 0 表示夏令时，0 表示非夏令时，小于 0 表示未知（让系统根据时区规则自行判断，一般传 -1 最省心）
  3. mktime() 按本地时区解释 tm；若想按 UTC 解释，可用 GNU 扩展 timegm()，或临时设置 TZ=UTC
  4. 输入时间超出 time_t 可表示范围时返回 (time_t)-1

settimeofday() — 设置系统时间

作用:: 设置系统的本地时间（即 CLOCK_REALTIME 墙上时钟）。对应 date -s 命令。

用法：

  • tv：要设置的时间（秒 + 微秒）
  • tz：时区参数，已废弃，传 NULL

注意事项：

  1. 需要 root 权限（或 CAP_SYS_TIME 能力），普通用户调用返回 -1，errno = EPERM
  2. tz 已废弃，传 NULL
  3. 现代替代：clock_settime(CLOCK_REALTIME, &ts)（纳秒精度）
  4. 慎用：修改 CLOCK_REALTIME 会影响系统上所有依赖墙上时钟的程序、日志时间戳、定时器等；由 NTP 自动同步的系统不要手动设置，会造成时间跳变

时间转换关系小结

time_t（秒）、struct tm（分解时间）、字符串三者之间的转换关系如下：

  • time_t → struct tm：localtime() / gmtime()
  • struct tm → time_t：mktime()（本地时区）/ timegm()（UTC，GNU 扩展）
  • time_t → 字符串：ctime()
  • struct tm → 字符串：asctime()（固定格式）/ strftime()（自定义格式）
  • 字符串 → time_t：strptime()（strftime() 的逆函数，GNU/POSIX 扩展）

进程时间

进程时间指的是进程从创建后（也就是程序运行后）到目前为止这段时间内使用 CPU 资源的时间总数。出于记录的目的，内核把 CPU 时间（进程时间）分为以下两个部分：

  • 用户 CPU 时间：进程在用户空间（用户态）下运行所花费的 CPU 时间，有时也称为虚拟时间（virtual time）
  • 系统 CPU 时间：进程在内核空间（内核态）下运行所花费的 CPU 时间，这是内核执行系统调用或代表进程执行的其它任务（如服务页错误）所花费的时间

进程时间 = 用户 CPU 时间 + 系统 CPU 时间，也就是总的 CPU 时间。

⚠️ 注意区分：进程时间（CPU 时间）是"程序占用了 CPU 多久"，与墙上时间（wall clock，程序从启动到结束过了多久）不同——程序 sleep 或等待 I/O 时不消耗 CPU 时间，但墙上时间在走。

函数 作用 成功返回 失败返回
times() 获取进程时间（用户/系统 CPU 时间，含子进程），以节拍为单位 节拍数 (clock_t)-1
clock() 获取总的进程 CPU 时间，以 CLOCKS_PER_SEC 为单位 CPU 时间 (clock_t)-1
getrusage() 获取进程资源使用统计（含用户/系统 CPU 时间、最大 RSS 等） 0 -1

times() — 获取进程时间

作用:: 获取当前进程时间，返回从过去任意一个时间点（譬如系统启动时间）所经过的时钟滴答数（其实就是系统节拍数），将（节拍数 / 节拍率）便可得到秒数。同时通过 struct tms 返回用户/系统 CPU 时间（含已终止子进程）。

用法：

  • buf：指向 struct tms 的指针，函数将各 CPU 时间（以节拍为单位）写入其中

注意事项：

  1. 返回值是墙上时间（wall clock）的节拍数，不是 CPU 时间；CPU 时间要看 struct tms 的四个字段
  2. 节拍率（每秒节拍数）用 sysconf(_SC_CLK_TCK) 获取（通常为 100），秒数 = 节拍数 / 节拍率
  3. tms_cutime / tms_cstime 只统计已终止（被 wait() 回收过）的子进程
  4. 用 times() 测代码耗时：前后各调一次，差值 / 节拍率 = 墙上秒数

注意事项：

  1. clock() 返回的是 CPU 时间，不是墙上时间！测 sleep 的耗时用它会得到 0
  2. 单位是 CLOCKS_PER_SEC：Linux 上该值为 1000000（微秒粒度），秒数 = 返回值 / CLOCKS_PER_SEC
  3. 不能区分用户态 / 内核态时间，需要区分用 times() 或 getrusage()
  4. 32 位系统上 clock_t 溢出周期约 72 分钟（2147483647 / 1000000 秒），长时运行程序注意

getrusage() — 获取进程资源使用情况 ⭐ 补充

作用:: 获取当前进程（或已终止子进程）的资源使用统计：用户/系统 CPU 时间、最大常驻内存（RSS）、页错误次数、上下文切换次数等。shell 内置命令 time 统计资源消耗就是基于它。

用法：

  • who：统计对象
who 取值 含义
RUSAGE_SELF 当前进程自身
RUSAGE_CHILDREN 所有已终止且被 wait() 回收的子进程
RUSAGE_THREAD 当前线程（Linux 专有）

注意事项：

  1. ru_utime / ru_stime 是 struct timeval（秒 + 微秒），与 times() 的节拍单位不同
  2. RUSAGE_CHILDREN 只统计已终止的子进程，且是所有已终止子进程的累计值
  3. ru_maxrss 单位是 KB（Linux）

随机数

C 库提供伪随机数生成器（PRNG）。所谓"伪"随机，是因为它们由确定的算法生成，给定相同种子（seed）就产生相同的序列——所以种子不同，序列才不同。

函数 作用 成功返回 失败返回
rand() / srand() 获取伪随机数 / 设置随机数种子 [0, RAND_MAX] 的整数 —
random() / srandom() 更高质量的伪随机数 / 设置种子 [0, 2^31-1] 的整数 —
getrandom() 内核熵池真随机数（安全场景） 写入字节数 -1

rand() & srand() — 伪随机数与种子

作用:: rand() 获取随机数，返回一个介于 0 到 RAND_MAX（包含）之间的值，也就是数学上的 [0, RAND_MAX]；srand() 设置随机数种子，一般常常将当前时间作为随机数种子赋值给参数 seed。

用法：

  • seed：随机数种子

注意事项：

  1. 没有调用 srand() 的情况下，rand() 会将 1 作为随机数种子；如果随机数种子相同，那么每一次启动应用程序所得到的随机数序列就是一样的
  2. 常见用法 srand(time(NULL))：种子是秒级的，同一秒内启动的多个进程会得到相同序列；可改进为 srand(time(NULL) ^ getpid())
  3. Linux 上 RAND_MAX = 2147483647（标准只要求至少 32767）
  4. rand() 是线性同余类算法，质量不高且可预测，绝不能用于密码、密钥、令牌等安全场景
  5. 取某个范围：rand() % n 有轻微分布偏差（rand() % n 使小余数略多），对质量要求高可用 rand() / (RAND_MAX / n + 1) 或直接用 random()

random() & srandom() — 更高质量的伪随机数 ⭐ 补充

作用:: 与 rand() / srand() 类似，但采用更优秀的算法（非线性加扰），生成 31 位的伪随机数，质量明显优于 rand()，是 GNU/Linux 下普通场景的推荐选择。

用法：

注意事项：

  1. 与 rand() 不同：random() 默认（未调用 srandom() 时）使用随机初始化（自动从熵源取种子），序列不可预测
  2. 种子是 32 位的，srandom(time(NULL) ^ getpid()) 仍是常用写法
  3. 同样不是加密安全的，安全场景用 getrandom()

getrandom() — 内核真随机数 ⭐ 补充

作用:: 直接从内核熵池获取随机数，用于密码学安全场景（密钥、令牌、salt 等）。可以理解为"打开 /dev/urandom 读取"的现代替代。

用法：

  • buf：存放随机数的缓冲区
  • buflen：请求的字节数
  • flags：0 即可；需要时可用 GRND_NONBLOCK（非阻塞，熵池未就绪时返回 EAGAIN）、GRND_RANDOM（使用 /dev/random 阻塞源）

注意事项：

  1. Linux 3.17+ 提供
  2. 与 rand() 的本质区别：rand() 是算法生成的伪随机数（可预测），getrandom() 来自内核收集的环境噪声（真随机），不可预测
  3. 普通场景（洗牌、抽样）用 random() 即可，性能更好；安全场景才需要 getrandom()

休眠

休眠（sleep）是让进程/线程主动让出 CPU，进入等待状态一段时间。休眠期间进程不消耗 CPU 时间，内核会在时间到后将其唤醒。注意：休眠只是"至少"睡够请求的时间，实际唤醒可能因调度略有延迟，但不会提前返回（除非被信号中断）。

函数 作用 成功返回 失败返回
sleep() 秒级休眠 0 剩余秒数（被信号中断时）
usleep() 微秒级休眠（已过时） 0 -1
nanosleep() 纳秒级高精度休眠 0 -1
clock_nanosleep() 指定时钟的纳秒级休眠（支持绝对时间） 0 错误码（直接返回，不设置 errno）

sleep() — 秒级休眠

作用:: 让当前进程休眠指定的秒数。

用法：

  • seconds：要休眠的秒数

注意事项：

  1. 精度只有秒级，需要更高精度用 nanosleep()
  2. 被信号中断时返回剩余秒数（不是 -1！），调用方可根据返回值决定是否继续休眠
  3. 底层基于 nanosleep() 实现

usleep() — 微秒级休眠

作用:: 让当前进程休眠指定的微秒数（1 秒 = 1,000,000 微秒）。

用法：

  • usec：要休眠的微秒数（POSIX 规定范围 0 ~ 1,000,000，即不超过 1 秒）

注意事项：

  1. POSIX.1-2001 已将该函数标记为过时（LEGACY），新代码推荐 nanosleep()
  2. 参数类型 useconds_t 是无符号整数，传负数会被当成很大的正数

nanosleep() — 高精度休眠

作用:: 以纳秒精度休眠指定的时间，是 Linux 下最常用的高精度休眠函数。

用法：

  • req：请求的休眠时间（秒 + 纳秒）
  • rem：被信号中断时，剩余未休眠的时间会写入 rem 指向的 struct timespec（传 NULL 表示不接收剩余时间）

注意事项：

  1. 返回值：成功休眠达到请求的时间间隔后返回 0；如果中途被信号中断或遇到错误，则返回 -1，并将剩余时间记录在 rem 指向的 struct timespec 结构体变量中（rem 不为 NULL 的情况下，如果为 NULL 表示不接收剩余时间），还会设置 errno 标识错误类型
  2. 信号中断后的正确处理：不能直接放弃，应把 rem 中的剩余时间重新作为 req 继续休眠
  3. req->tv_nsec 取值范围 0 ~ 999,999,999（超出返回 EINVAL）
  4. 休眠的是当前线程，多线程程序中只挂起调用线程
  5. 实际休眠时间可能因内核调度略长于请求值（四舍五入到下一个时钟节拍）

clock_nanosleep() — 指定时钟的高精度休眠 ⭐ 补充

作用:: nanosleep() 的增强版：可以指定使用哪个时钟（CLOCK_REALTIME / CLOCK_MONOTONIC），并且支持绝对时间休眠（休眠到某个绝对时刻为止），适合实时任务。

用法：

  • clockid：时钟，常用 CLOCK_REALTIME（墙上时钟）或 CLOCK_MONOTONIC（单调时钟）
  • flags：0 表示相对休眠（睡 request 那么久）；TIMER_ABSTIME 表示绝对休眠（直到时钟到达 request 指定的绝对时刻）
  • request：相对休眠时为休眠时长；绝对休眠时为目标绝对时间
  • remain：相对休眠且被信号中断时，剩余时间写入这里（绝对休眠模式该参数无意义）

注意事项：

  1. 返回错误码而不是设置 errno：判断失败用 if (ret != 0)，其中 ret == EINTR 表示被信号中断
  2. 绝对休眠（TIMER_ABSTIME）的好处：被信号中断后重新调用即可（目标时刻不变），无需计算剩余时间，非常适合周期性的实时任务（不累积漂移）
  3. 相对休眠的时钟建议用 CLOCK_MONOTONIC，避免系统时间被修改影响休眠

申请堆内存

进程的虚拟地址空间中，堆（heap） 是用于动态内存分配的区域，向上（高地址）增长。C 语言通过 malloc() 系列函数从堆上分配内存。堆内存的生命周期由程序员管理：分配后必须记得释放，否则会造成内存泄漏。

函数 作用 成功返回 失败返回
malloc() 分配 size 字节（不初始化） 内存指针 NULL
free() 释放堆内存 — —
calloc() 分配 nmemb × size 字节并清零 内存指针 NULL
realloc() 调整已分配内存的大小 新内存指针 NULL

malloc() & free() — 分配与释放堆内存

作用:: malloc() 在堆区分配一块指定大小的连续内存空间，用来存放数据。这块内存空间在函数执行完成后不会被初始化，它们的值是未知的。free() 释放之前由 malloc() / calloc() / realloc() 分配的内存。

用法：

  • size：要分配的字节数
  • ptr：要释放的内存指针（必须是 malloc/calloc/realloc 返回的指针）

注意事项：

  1. 必须检查返回值：malloc() 失败返回 NULL，不检查就使用会导致空指针解引用崩溃
  2. free() 只接受堆上由分配函数返回的指针：不能 free 栈上/静态变量指针，不能重复 free 同一指针（行为未定义，可能崩溃）
  3. 释放后建议将指针置 NULL（free(p); p = NULL;），防止"悬空指针"被二次使用
  4. 内存泄漏：当进程终止时，内核会将其占用的所有内存都返还给操作系统，这包括在堆内存中由 malloc() 函数所分配的内存空间，但最好能够在程序中显式调用 free() 释放内存：
    • 显式调用 free() 能使程序具有更好的可读性和可维护性
    • 对于很多程序来说，申请的内存并不是在程序的生命周期中一直需要，大多数情况下都是根据代码需求动态申请、释放的；如果申请的内存对程序来说已经不再需要了，就应该把它释放、归还给操作系统，如果持续占用，将会导致内存泄漏
  5. malloc(0) 行为是实现定义的：可能返回 NULL 或一个可以 free() 的唯一指针，都不算错误
  6. 底层实现：小块内存基于 brk/sbrk 扩展堆，大块（默认 > 128KB）直接用 mmap 映射，free() 时归还给内核
  7. 检测内存问题：valgrind、GCC/Clang 的 -fsanitize=address（ASan）

calloc() — 分配并清零

作用:: 在堆中动态地分配 nmemb 个长度为 size 的连续空间，并将每一个字节都初始化为 0。

用法：

  • nmemb：元素个数
  • size：每个元素的字节数

注意事项：

  1. 与 malloc(nmemb * size) 的区别：
    • calloc() 会清零；malloc() 不初始化
    • calloc() 内部会检测 nmemb * size 乘法溢出，溢出时返回 NULL 并设置 errno = ENOMEM；malloc() 不会检测，溢出后会分配一个过小的块导致越界写
  2. 分配大数组时优先用 calloc()（更安全）
  3. 释放同样用 free()

realloc() — 调整内存大小 ⭐ 补充

作用:: 调整之前由 malloc() / calloc() / realloc() 分配的内存块大小（扩大或缩小）。扩大时若原位置空间不足，会搬移到新位置，旧内容自动拷贝过去；缩小时内容保留前部分。

用法：

  • ptr：原内存指针（若为 NULL，等价于 malloc(size)）
  • size：新的大小（若为 0，等价于 free(ptr)，但行为是实现定义，谨慎）

注意事项：

  1. 经典坑：不要直接 ptr = realloc(ptr, new_size)——若 realloc() 失败返回 NULL，会把原指针覆盖掉，导致原内存泄漏且无法释放。正确写法：
  1. 扩大后新增的部分内容未初始化
  2. 返回的地址可能变了，所有指向旧内存的指针都会失效，必须用新返回值

💡 堆内存小结：malloc（分配）→ calloc（分配+清零）→ realloc（调整）→ free（释放），四者配套使用；检查 NULL、不重复 free、释放后置 NULL，是避免内存问题的三条铁律。

内存对齐

为什么需要对齐：CPU 访问对齐的数据更快——许多架构（如 ARM）访问未对齐地址会触发异常或性能惩罚；硬件外设（DMA）、SIMD 指令（如 AVX 需要 32 字节对齐）对内存地址有明确的对齐要求。

默认对齐：malloc()、calloc() 分配内存返回的地址其实也是对齐的，但它俩的对齐都是固定的，并且对齐的字节边界比较小——譬如在 32 位系统中通常是以 8 字节为边界进行对齐，在 64 位系统中是以 16 字节进行对齐。这个对齐度保证任何内置类型（double、long long）都能对齐访问，但满足不了 SIMD、DMA 等更大对齐的需求。如果想实现更大字节的对齐，则需要使用其他函数。

对齐要求：对齐数必须是 2 的幂（如 2、4、8、16、32、64、4096）。

函数 作用 成功返回 失败返回
posix_memalign() 按指定对齐数分配堆内存（POSIX 标准） 0 错误码（不设置 errno）
aligned_alloc() 按指定对齐数分配堆内存（C11 标准） 内存指针 NULL
memalign() 按指定对齐数分配（过时，非标准） 内存指针 NULL
valloc() / pvalloc() 页对齐分配（过时） 内存指针 NULL

posix_memalign() — 指定对齐分配

作用:: 用于在堆上分配 size 个字节大小的对齐内存空间，将 *memptr 指向分配的空间，分配的内存地址将是参数 alignment 的整数倍。

用法：

  • memptr：指向指针的指针，成功时 *memptr 保存分配到的内存地址
  • alignment：对齐字节数。必须是 2 的幂次方（譬如 24、25、2^8 等），同时也要是 sizeof(void *) 的整数倍——对于 32 位系统来说 sizeof(void *) 等于 4，如果是 64 位系统 sizeof(void *) 等于 8
  • size：分配大小（字节）

注意事项：

  1. 失败时不返回 NULL，而是返回错误码：EINVAL（alignment 不是 2 的幂或不是 sizeof(void *) 的倍数）、ENOMEM（内存不足），且 *memptr 的值未定义
  2. 释放方式：用 free()（与 malloc() 一样）
  3. 是 POSIX 标准推荐的首选对齐分配函数

aligned_alloc() — C11 对齐分配

作用:: 用于分配 size 个字节大小的内存空间，返回指向该空间的指针，且地址按 alignment 对齐。是 C11 标准函数，与 posix_memalign() 功能等价。

用法：

  • alignment：对齐字节数（必须是 2 的幂）
  • size：分配大小（字节）

注意事项：

  1. C11 要求 size 必须是 alignment 的整数倍，否则行为未定义（Linux 上 glibc 会返回 NULL 并设置 errno = EINVAL）——这是与 posix_memalign() 最大的区别，后者对 size 无此要求
  2. 失败返回 NULL（与 malloc() 风格一致）
  3. 用 free() 释放；glibc 2.16+ 支持，需 C11 标准（-std=c11）

memalign() / valloc() / pvalloc() — 过时函数

作用:: 老的非标准对齐分配函数（BSD/GNU 起源），功能已被 posix_memalign() 取代：

  • memalign(alignment, size)：按 alignment 对齐分配（alignment 必须是 2 的幂，但不要求是 sizeof(void *) 的倍数）
  • valloc(size)：按页面大小对齐分配（等价 memalign(sysconf(_SC_PAGESIZE), size)）
  • pvalloc(size)：将 size 向上取整到页面大小后按页对齐分配

注意事项：

  1. 三者均为过时函数（valloc/pvalloc 在 POSIX.1-2001 中被标记 LEGACY，glibc 中已弃用），新代码不要使用
  2. 释放均用 free()
  3. 统一替代品：posix_memalign()（POSIX）或 aligned_alloc()（C11）

💡 补充：结构体的对齐由编译器自动处理——结构体成员之间可能被填充（padding）字节以对齐，可用 offsetof(type, member) 查看成员偏移，用 sizeof 查看含填充的总大小；__attribute__((packed)) 可取消填充（省空间但访问变慢，某些架构上还不能直接访问未对齐成员）。

proc 文件系统

基本概念

proc 文件系统是一个虚拟文件系统，它以文件系统的方式为应用层访问系统内核数据提供了接口，用户和应用程序可以通过 proc 文件系统得到系统信息和进程相关信息。

  • proc 文件系统是动态创建的，文件本身并不存在于磁盘当中、只存在于内存当中，与 devfs 一样，都被称为虚拟文件系统
  • 内核构建 proc 虚拟文件系统，它会将内核运行时的一些关键数据信息以文件的方式呈现在 proc 文件系统下的一些特定文件中，这样相当于将一些不可见的内核中的数据结构以可视化的方式呈现给应用层
  • 挂在 /proc 目录下，大部分文件是只读的，文件大小显示为 0（内容是动态生成的）

核心系统信息文件

文件 内容
/proc/cmdline 内核启动参数
/proc/cpuinfo CPU 的型号、频率、核心数等详细信息
/proc/meminfo 系统内存的总大小、已用内存和剩余内存等
/proc/uptime 系统启动了多长时间（第一个数），以及空闲时间（第二个数）
/proc/version 当前系统的 Linux 内核版本和编译器版本
/proc/loadavg 系统的平均负载（1分钟、5分钟、15分钟）
/proc/iomem IO 设备的内存使用情况
/proc/interrupts 显示被占用的中断号和占用者相关的信息
/proc/ioports IO 端口的使用情况
/proc/kcore 系统物理内存映像，不可读取（权限受限）
/proc/modules 加载的模块列表
/proc/mounts 挂载的文件系统列表
/proc/partitions 系统识别的分区表
/proc/swaps 交换分区的利用情况
/proc/stat 内核/系统统计信息（CPU 时间、上下文切换、启动时间等）

💡 /proc/self 是一个指向当前进程自身目录的符号链接（等价于 /proc/当前PID），程序内访问自己的进程信息时直接用 /proc/self/... 即可，不用先获取 PID。

路径 内容

网络与设备控制

  • /proc/net/：存放网络相关的统计信息，如路由表（route）、网络连接（netstat）等
  • /proc/sys/：用来读取和修改内核运行参数的控制中心（例如通过修改这里的某些文件可以调整网络转发或内存分配）。它对应 sysctl 命令（如 /proc/sys/net/ipv4/ip_forward ↔︎ sysctl net.ipv4.ip_forward）

  1. proc 文件是动态生成的：每次 open/read 时内核现场生成内容，所以 ls -l 看到大小是 0，但读出来的内容有数据
  2. 大多数文件只读；只有 /proc/sys/ 下的一部分文件可写（且需要 root 权限）
  3. /proc/kcore 等内容涉及系统内存映像，普通用户无权限读取
  4. 编程时优先考虑库函数/系统调用（sysinfo()、uname() 等），proc 文件适合命令行查看、shell 脚本和需要解析细粒度数据的场景
