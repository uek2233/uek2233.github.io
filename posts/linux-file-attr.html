文件属性与目录

学习 Linux 应用编程时整理的笔记，涵盖：文件类型、文件属性（stat）、文件属主、文件权限、文件时间、软/硬链接、目录操作、删除与重命名。

阅读建议：先搞清楚「文件是什么」（类型与属性），再理解「谁能碰它」（属主与权限），最后掌握「怎么组织它」（链接与目录）。

文件类型

Linux 系统下，可以通过 stat 命令或者 ls -l 命令查看文件类型（结果的第一列就是类型字符）。

类型字符 文件类型 说明
- 普通文件 文本文件、二进制文件、源代码文件等
d 目录文件 目录也是一种特殊文件，记录该目录下的文件名与 inode 编号
c 字符设备文件 文件系统虚拟出来的字符设备，一般位于 /dev/ 目录，由内存维护，关机后消失
b 块设备文件 同上，按块访问的设备（如磁盘）
l 符号链接文件 内容指向另一个文件的路径，操作时会被转移到目标文件
s 套接字文件 用于网络通信
p 管道文件（FIFO） 用于进程间通信

在代码中判断文件类型：文件模式 st_mode 的低 12 位是权限位，高 4 位（S_IFMT 掩码）是文件类型。用 st_mode & S_IFMT 与类型宏比较，或直接用 S_ISREG() 等辅助宏：

类型宏 辅助宏 对应类型
S_IFREG S_ISREG(m) 普通文件
S_IFDIR S_ISDIR(m) 目录
S_IFLNK S_ISLNK(m) 符号链接
S_IFCHR S_ISCHR(m) 字符设备
S_IFBLK S_ISBLK(m) 块设备
S_IFIFO S_ISFIFO(m) 管道/FIFO
S_IFSOCK S_ISSOCK(m) 套接字

stat() & fstat() & lstat() — 获取文件属性

Linux 下的 stat 命令内部就是调用 stat() 系统调用来获取文件属性的。

函数 作用 成功返回 失败返回
stat() 从文件路径出发获取文件属性（跟随符号链接） 0 -1
fstat() 从文件描述符出发获取文件属性（跟随符号链接） 0 -1
lstat() 获取符号链接本身的属性（不跟随） 0 -1

💡 三者获取到的都是同一个 struct stat 结构体，区别只在于"从哪出发"和"是否解引用符号链接"。

struct stat 结构体

📌 时间字段的旧写法 st_atime / st_mtime / st_ctime 是兼容宏，等价于 st_atim.tv_sec，新代码建议直接使用 st_atim.tv_sec。

stat() — 从文件路径获取属性

作用:: 通过文件路径名获取文件属性，不需要先打开文件

用法：

  • pathname：文件路径（绝对路径或相对路径）
  • statbuf：指向 struct stat 结构体的指针，用于接收文件属性

注意事项：

  1. 不需要打开文件，直接由内核根据路径解析并填充属性
  2. stat() 会解引用符号链接——如果 pathname 是符号链接，获取的是链接目标文件的属性
  3. 常见的 errno：ENOENT（文件不存在）、EACCES（无访问权限）、ENOTDIR（路径中某部分不是目录）

fstat() — 从文件描述符获取属性

作用:: 通过文件描述符获取已打开文件的属性

用法：

  • fd：open() 返回的文件描述符
  • statbuf：接收文件属性的 struct stat 指针

注意事项：

  1. 使用 fstat() 前需要先用 open() 打开文件拿到文件描述符
  2. 好处：无需考虑路径中的竞态问题（TOCTOU，time-of-check to time-of-use），属性查询与文件操作共用同一个文件描述符更安全
  3. 也常用于查询 open() 无法直接返回的信息，比如先 open 再 fstat 判断文件类型

lstat() — 获取符号链接本身的属性

作用:: 获取符号链接文件本身的属性（不跟随链接）

用法：

  • pathname：文件路径
  • statbuf：接收文件属性的 struct stat 指针

注意事项：

  1. lstat() 与 stat() 的唯一区别：当 pathname 是符号链接时，lstat 返回的是链接文件自身的信息（st_mode 中类型为 S_IFLNK），而 stat/fstat 返回的是链接目标的信息
  2. 如果 pathname 不是符号链接，lstat 与 stat 行为完全一致
  3. 常用场景：判断一个文件是否为符号链接

文件属主

Linux 系统会为每一个用户或用户组分配一个 ID，将用户名或用户组名与对应的 ID 关联起来，系统通过用户 ID（UID）或组 ID（GID）就可以识别出不同的用户和用户组。

  • 文件在创建时，其所有者就是创建该文件的用户
  • 文件的用户 ID 和组 ID 分别由 struct stat 中的 st_uid 和 st_gid 指定

Linux 下的每一个文件都有与之相关联的用户 ID 和组 ID，对于一个进程来说亦是如此：

  • 实际用户 ID & 实际组 ID：用于标识"执行该进程的是谁"（登录身份）
  • 有效用户 ID & 有效组 ID & 附属组 ID：进程所持有的概念，用于文件访问权限检查。当进程对文件进行读写操作时，系统通过 st_mode 字段配合有效用户/有效组来检查权限，而不是实际用户/实际组

chown() 修改文件的属主/属组（按路径，跟随符号链接） 0 -1
fchown() 修改文件的属主/属组（按文件描述符） 0 -1
lchown() 修改符号链接本身的属主/属组（不跟随） 0 -1
getuid() 获取进程的实际用户 ID 实际 UID —
getgid() 获取进程的实际组 ID 实际 GID —
geteuid() 获取进程的有效用户 ID 有效 UID —
getegid() 获取进程的有效组 ID 有效 GID —

chown() — 修改文件属主/属组

作用:: 修改指定文件的用户 ID（属主）和组 ID（属组）

用法：

  • pathname：文件路径
  • owner：新的用户 ID；传 -1 表示不修改属主
  • group：新的组 ID；传 -1 表示不修改属组

注意事项：

  1. 只有超级用户进程才能更改文件的用户 ID（owner）
  2. 普通用户进程可以将文件的组 ID 修改为其所从属的任意附属组 ID，前提条件是该进程的有效用户 ID 等于文件的用户 ID
  3. 修改属主/属组会更新文件的 st_ctim（状态变更时间），并可能清除 SUID/SGID 位
  4. chown() 会解引用符号链接；若想修改链接本身，使用 lchown()

fchown() & lchown() — 变体

作用:: fchown() 通过文件描述符修改属主/属组；lchown() 修改符号链接本身的属主/属组

用法：

  • fd：文件描述符（fchown）
  • pathname：文件路径（lchown，不跟随符号链接）

注意事项：

  1. fchown() 适合"先 open 再修改"的场景，避免路径竞态
  2. lchown() 与 chown() 唯一区别：pathname 是符号链接时，修改的是链接文件自身而不是目标文件

  2. 进程执行设置了 SUID 位的程序时，有效 ID 会变，但实际 ID 不变——此时用 getuid() 拿到的是"真实用户"

  1. 有效 ID 才是文件访问权限检查依据的身份

文件权限

文件的权限分为两大类：

  • 普通权限：对文件的读（r）、写（w）以及执行（x）
  • 特殊权限：对文件的附加权限，如 Set-User-ID（SUID）、Set-Group-ID（SGID）以及 Sticky（粘滞位）

📌 目录权限与普通文件不同：在目录下创建文件或删除原有文件，需要同时拥有对该目录的执行（x）和写（w）权限——x 权限决定能否"进入"目录，w 权限决定能否"增删"目录项。

普通权限

使用 ls -l 命令或 stat 命令可以查看到文件的访问权限：

  • r 表示具有读权限
  • w 表示具有写权限
  • x 表示具有执行权限

st_mode 权限表示宏：

st_mode 权限宏 含义
S_IRUSR 文件所有者读权限
S_IWUSR 文件所有者写权限
S_IXUSR 文件所有者执行权限
S_IRGRP 同组用户读权限
S_IWGRP 同组用户写权限
S_IXGRP 同组用户执行权限
S_IROTH 其它用户读权限
S_IWOTH 其它用户写权限
S_IXOTH 其它用户执行权限

ls -l 输出示例：-rwxr-xr-- 表示属主 rwx、属组 r-x、其他 r--，对应八进制 0754。

特殊权限

st_mode 中特殊权限占 3 个 bit 位，从高位到低位依次表示：set-user-ID 位、set-group-ID 位以及 sticky 位。

特殊权限 含义
S_ISUID set-user-ID 位权限（八进制 4000）
S_ISGID set-group-ID 位权限（八进制 2000）
S_ISVTX Sticky 位权限（八进制 1000）
  • SUID（set-user-ID）：如果文件的 set-user-ID 位被设置，内核会将进程的有效用户 ID 设置为该文件的用户 ID（文件所有者 ID），意味着该进程直接获取了文件所有者的权限、以文件所有者的身份操作该文件。典型例子：/usr/bin/passwd 属主是 root 且带 SUID 位，普通用户执行它就能以 root 身份修改 /etc/shadow。
  • SGID（set-group-ID）：进程对文件操作进行权限检查时，若文件的 set-group-ID 位被设置，内核会将进程的有效用户组 ID 设置为该文件的用户组 ID，意味着进程以文件所属组成员的身份操作该文件。若设置在目录上，则该目录下新建的文件/目录会继承目录的组 ID。
  • Sticky（粘滞位）：一般只用于目录（如 /tmp，权限 1777）。设置了粘滞位的目录中，只有文件的所有者、目录的所有者或超级用户才能删除/重命名该目录下的文件，其他用户即使对目录有写权限也不能删除别人的文件。

access() — 检查文件权限

作用:: 检查当前进程对指定文件是否具有某种访问权限

用法：

  • pathname：文件路径
  • mode：要检查的权限，可组合：
mode 取值 含义
F_OK 检查文件是否存在
R_OK 检查是否可读
W_OK 检查是否可写
X_OK 检查是否可执行

注意事项：

  1. access() 使用进程的实际用户 ID / 实际组 ID 进行检查，而 open() 等系统调用使用的是有效 ID——所以 SUID 程序里两者结果可能不一致，这正是 access() 存在的意义（判断"真实用户"能否访问）
  2. access() 会解引用符号链接
  3. 常见的检查失败 errno：EACCES（权限不足）、ENOENT（文件不存在）、EROFS（只读文件系统上检查写）

chmod() & fchmod() — 修改文件权限

作用:: chmod() 通过路径修改文件权限位；fchmod() 使用文件描述符来代替文件路径

用法：

  • pathname / fd：文件路径 / 文件描述符
  • mode：新权限，可用八进制数（如 0755）或权限宏按位或组合（如 S_IRUSR | S_IWUSR | S_IXUSR）

注意事项：

  1. 只有文件所有者或超级用户才能修改文件的权限
  2. chmod() 会解引用符号链接，修改的是链接目标文件的权限；符号链接本身的权限在 Linux 上不可修改（总是 0777）
  3. 修改权限会更新 st_ctim，不影响 st_atim/st_mtim，也不改变文件内容
  4. 非特权用户执行 chmod 时，文件的 SUID/SGID 位可能被内核自动清除（防止借机提权）

umask() — 设置文件创建掩码

作用:: 设置进程的文件创建掩码。新建文件时，文件实际的权限并不等于我们设置的权限，而是通过 mode & ~umask 得到实际权限

用法：

  • mask：新的 umask 值（八进制，如 0022），含义是"创建时要屏蔽掉的权限位"

注意事项：

  1. 例如 mode 参数指定为 0777，假设 umask 为 0002，那么实际权限为 0777 & (~0002) = 0775——即创建时屏蔽掉了"其他用户写"权限
  2. umask 是进程属性，子进程会继承父进程的 umask；shell 的默认 umask 一般是 0022，所以普通用户创建文件默认为 0644、目录默认为 0755
  3. 想精确控制权限时，可先 umask(0) 再 open/mkdir
  4. umask 只影响新建的文件/目录，不影响已存在文件的权限

文件的时间属性

字段 说明
st_atim 文件最后被访问的时间（Access）
st_mtim 文件内容最后被修改的时间（Modify）
st_ctim 文件状态最后被改变的时间（Change）
  • st_atim（访问时间）：读取文件内容时更新（如 read()）；只打开文件、修改权限不会更新 atime
  • st_mtim（修改时间）：文件正文数据发生变化时更新（如 write() 写入数据），是最常用的"文件改动时间"
  • st_ctim（状态变更时间）：inode 信息发生修改时更新：修改权限 chmod、属主 chown、硬链接计数、文件大小变化等

📌 注意：ctime 不是创建时间（Linux 没有标准的文件创建时间字段），它是"状态变更时间"（change time）。

函数 作用 成功返回 失败返回
utime() 修改文件访问/修改时间（秒级精度） 0 -1
utimes() 修改文件访问/修改时间（微秒级精度） 0 -1
futimens() 通过 fd 修改时间（纳秒级，可单独指定 atime/mtime） 0 -1
utimensat() 通过路径修改时间（纳秒级，可控制是否跟随符号链接） 0 -1

utime() — 修改时间属性（秒级）

作用:: 显式修改文件的访问时间和修改时间

用法：

  • filename：文件路径
  • times：指向 utimbuf 的指针；传 NULL 表示将 atime/mtime 都设为当前时间

注意事项：

  1. 只能修改 atime 和 mtime，无法修改 ctime——ctime 由内核维护，一旦调用 utime() 修改了时间，ctime 会自动更新为当前时间
  2. 权限要求：文件的所有者或超级用户；普通用户可通过传 NULL 把自己的 atime 设为当前时间

utimes() — 修改时间属性（微秒级）

作用:: 与 utime() 相同，但使用 timeval 结构，支持微秒精度

用法：

  • filename：文件路径
  • times：长度为 2 的数组，times[0] 是访问时间，times[1] 是修改时间；传 NULL 表示都设为当前时间

注意事项：

  1. 精度比 utime() 高（微秒级），但还达不到 futimens() 的纳秒级
  2. 权限规则与 utime() 相同

futimens() & utimensat() — 修改时间属性（纳秒级）

作用:: 更精细的时间修改接口，支持纳秒精度，且可只修改其中一个时间（另一个保持不变）

用法：

  • fd：文件描述符（futimens）
  • dirfd + pathname：路径定位（utimensat）；dirfd 传 AT_FDCWD 表示相对于当前工作目录
  • times：长度为 2 的数组，times[0] 是 atime，times[1] 是 mtime
  • flags：可为 0，或 AT_SYMLINK_NOFOLLOW（不跟随符号链接，修改链接本身）

times 中的特殊值（tv_nsec）：

特殊值 含义
UTIME_NOW 该时间字段设置为当前时间
UTIME_OMIT 该时间字段保持不变

注意事项：

  1. UTIME_OMIT 配合 UTIME_NOW 可以只更新其中一个时间，例如 times[0] = {0, UTIME_NOW}、times[1] = {0, UTIME_OMIT} 表示只把 atime 设为当前时间
  2. utimensat() 是 POSIX 接口，futimens() 是其 fd 版本，两者精度都是纳秒
  3. 权限规则：文件所有者或超级用户；传 NULL 等价于两个都设 UTIME_NOW

符号链接：软链接与硬链接

ln 命令可以为一个文件创建软链接文件或硬链接文件，用法如下：

  • 硬链接：硬链接文件与源文件拥有相同的 inode 号，对文件系统来说是完全平等的关系，仅仅只是文件名字不同而已。inode 数据结构中会记录文件的链接数（硬链接数）：每创建一个硬链接，inode 节点上的链接数就加一；每删除一个硬链接，链接数就减一，直到为 0，inode 节点和对应的数据块才会被文件系统回收。
  • 软链接：软链接文件与源文件有着不同的 inode 号，意味着它们有着不同的数据块，但软链接文件的数据块中存储的是源文件的路径名，链接文件可以通过这个路径找到被链接的源文件，它们之间类似于一种"主从"关系。当源文件被删除之后，软链接文件依然存在，但此时它指向的是一个无效的文件路径，这种链接文件被称为悬空链接（dangling link）。
对比项 硬链接 软链接
inode 号 与源文件相同 与源文件不同（有独立 inode）
数据块 与源文件共享 存储的是源文件的路径名
对目录 不能创建硬链接（超级用户在某些文件系统上可以） 可以对目录创建软链接
跨文件系统 要求链接文件和源文件位于同一文件系统 可以跨越不同文件系统
源文件不存在 无法创建（源必须存在） 可以对不存在的文件创建软链接（会产生悬空链接）
删除源文件 链接仍然有效（指向同一 inode） 链接失效（悬空链接）
函数 作用 成功返回 失败返回
link() 创建硬链接 0 -1
symlink() 创建软链接 0 -1
readlink() 读取软链接文件中存储的路径 写入的字节数 -1

link() — 创建硬链接

作用:: 为指定文件创建一个新的硬链接（目录项）

用法：

  • oldpath：已存在的源文件路径
  • newpath：要创建的硬链接路径

注意事项：

  1. 创建硬链接后，文件 inode 的链接数 st_nlink 加 1
  2. 硬链接的限制：不能对目录创建硬链接（EPERM）；不能跨文件系统（EXDEV）
  3. 若 newpath 已存在，返回 EEXIST 错误
  4. link() 不会解引用符号链接：如果 oldpath 是符号链接，创建的是指向该符号链接的硬链接（实际很少这么用）

symlink() — 创建软链接

作用:: 创建一个符号链接，链接内容为指定的路径字符串

用法：

  • target：链接指向的目标路径（可以是相对路径、绝对路径，甚至不存在的路径）
  • linkpath：要创建的符号链接文件路径

注意事项：

  1. target 只是被当作字符串存入链接文件，不要求目标存在——所以可以对不存在的文件创建软链接，形成悬空链接
  2. 软链接有自己的 inode，st_size 是 target 字符串的长度
  3. 若 linkpath 已存在，返回 EEXIST 错误

readlink() — 读取软链接文件

作用:: 读取符号链接文件中存储的目标路径字符串

用法：

  • pathname：符号链接文件路径
  • buf：存放读取结果的缓冲区
  • bufsiz：缓冲区大小

注意事项：

  1. open() 打开一个链接文件时，打开的是它指向的文件而非链接本身，所以不能通过 open + read 来读取软链接中存储的路径信息——必须使用 readlink()
  2. readlink() 不会在 buf 末尾自动添加 '\0'，需要自己根据返回值补上，否则 printf 会越界
  3. 缓冲区不够大时，结果会被截断（不报错）

目录

目录的存储形式由 inode 节点和目录块构成。目录块中有多个目录项，每一个目录项对应目录下的某一个文件，目录项中记录了该文件的文件名以及它的 inode 节点编号。

💡 目录的"内容"就是一张"文件名 → inode 编号"的映射表。ls 一个目录实际上就是遍历这张表。

函数 作用 成功返回 失败返回
mkdir() 创建目录 0 -1
rmdir() 删除空目录 0 -1
opendir() 打开目录，返回目录流句柄 DIR * NULL
closedir() 关闭目录流 0 -1
readdir() 读取下一条目录项 struct dirent * NULL（末尾/出错）
rewinddir() 将目录流重置到起点 无（void） —
getcwd() 获取当前工作目录 buf 指针 NULL
chdir() 改变当前工作目录（路径） 0 -1
fchdir() 改变当前工作目录（fd） 0 -1

mkdir() & rmdir() — 创建/删除目录

作用:: mkdir() 创建一个新目录；rmdir() 删除一个空目录

用法：

  • pathname：目录路径
  • mode：目录权限（八进制，如 0755），受 umask 影响：实际权限 = mode & ~umask

注意事项：

  1. mkdir() 创建的目录会默认包含 . 和 .. 两个目录项
  2. 若目录已存在，mkdir 返回 EEXIST
  3. rmdir() 只能删除空目录；目录非空时返回 ENOTEMPTY（或 EEXIST）
  4. 删除非空目录需要递归删除其中所有文件，C 标准库没有直接接口，可自己递归或使用 nftw() 遍历删除

opendir() & closedir() — 打开、关闭目录

作用:: opendir() 打开一个目录，返回指向该目录的句柄（DIR 指针）；closedir() 关闭目录流

用法：

  • name：目录路径
  • dirp：opendir() 返回的目录流指针

注意事项：

  1. DIR 是目录流结构体，类似 FILE，通过它配合 readdir() 逐条读取目录项
  2. 使用完毕必须 closedir() 释放资源
  3. 常见的失败 errno：ENOENT（目录不存在）、ENOTDIR（路径不是目录）、EACCES（无权限）

readdir() — 读取目录项

作用:: 每调用一次就从目录流中读取下一条目录项，并返回 struct dirent 结构体指针

用法：

  • dirp：opendir() 返回的目录流指针

注意事项：

  1. 遇到目录结尾或是出错时，readdir() 都返回 NULL，需要通过 errno 区分：
  1. 返回的 struct dirent * 指向静态分配的缓冲区，下一次调用 readdir() 会覆盖它——若需保存多个目录项，要自己拷贝内容
  2. d_type 在某些文件系统上不可靠（返回 DT_UNKNOWN），需要准确的类型时，可以用 lstat() 自行判断（记得排除 . 和 ..）
  3. readdir() 不是线程安全的（多个线程共享同一个 DIR* 流时），每个线程应使用独立的 DIR*；glibc 还提供了 readdir_r()（已废弃）和基于 dirfd() + getdents() 的方案

rewinddir() — 重置目录流

作用:: 将目录流的位置重置为目录起点，下次 readdir() 从第一条目录项开始读

用法：

  • dirp：目录流指针

注意事项：

  1. 常用于需要重复遍历目录的场景，省去重新 opendir/closedir
  2. 相关的还有 telldir()（获取当前位置）和 seekdir()（定位到指定位置），可实现更灵活的位置控制

getcwd() — 获取当前工作目录

作用:: 获取进程的当前工作目录的绝对路径

用法：

  • buf：存放路径的缓冲区；也可传 NULL 让 glibc 自动 malloc（此时 size 传 0）
  • size：缓冲区大小

注意事项：

  1. 缓冲区太小会返回 ERANGE 错误
  2. 传 NULL、size=0 时（glibc 扩展），函数会 malloc 分配足够空间，调用者必须 free()
  3. shell 的 pwd 命令内部就是调用 getcwd()

chdir() & fchdir() — 改变当前工作目录

作用:: 更改进程的当前工作目录

用法：

  • path：要切换到的目录路径（chdir，跟随符号链接）
  • fd：已打开的目录的文件描述符（fchdir）

注意事项：

  1. 只影响当前进程的工作目录，不影响父进程，也不影响 shell
  2. 切换后，相对路径的解析基准发生变化
  3. fchdir() 与 chdir() 等价，但用 fd 可以避免路径竞态，也方便"先记录目录再切走、再切回来"的模式

删除文件

函数 作用 成功返回 失败返回
unlink() 删除文件的目录项（硬链接），链接计数减 1 0 -1
remove() 删除文件（内部调 unlink）或空目录（内部调 rmdir） 0 -1

unlink() — 删除文件

作用:: 移除/删除一个硬链接。实质是移除 pathname 指定的文件路径对应的目录项，并将文件的 inode 链接计数减 1，只有当链接计数变为 0 时，该文件的内容才可被删除

用法：

  • pathname：要删除的文件路径

注意事项：

  1. unlink() 删除的是目录项（链接），不是立即删除文件数据；只有当 inode 链接计数归 0 时，inode 和数据块才会被回收
  2. 若文件仍被进程打开（open 未关闭），即使 unlink 成功，文件内容也会保留到所有 fd 关闭之后才真正释放——这是实现"临时文件"的经典技巧：open 后立即 unlink，进程退出后文件自动消失
  3. unlink() 并不会对软链接进行解引用：若 pathname 指定的文件是软链接，删除的是软链接文件本身，而不是它指向的目标
  4. unlink() 不能删除目录（会返回 EISDIR），删除目录请用 rmdir()

remove() — 删除文件

作用:: 用于移除一个文件或空目录（跨平台的 C 标准库函数）

用法：

  • pathname：要删除的文件或空目录路径

注意事项：

  1. remove() 内部实现：对文件调用 unlink()，对目录调用 rmdir()，所以可以统一处理"文件或空目录"
  2. remove() 不对软链接进行解引用：删除的是软链接本身
  3. 比 unlink() 可移植性更好（C 标准库函数，Windows 上也能用）

文件重命名

rename() — 重命名/移动文件

作用:: 既可以对文件进行重命名，又可以将文件移至同一文件系统中的另一个目录下

用法：

  • oldpath：原路径
  • newpath：新路径

注意事项：

  1. rename() 调用仅操作目录条目，而不移动文件数据（不改变文件 inode 编号、不移动数据块中存储的内容）；重命名既不影响指向该文件的其它硬链接，也不影响已经打开该文件的进程
  2. 若 newpath 指定的文件或目录已经存在，则将其覆盖（文件）
  3. 若 newpath 和 oldpath 指向同一个文件，则不发生变化（且调用成功）
  4. rename() 对其两个参数中的软链接均不进行解引用：如果 oldpath 是软链接，将重命名该软链接本身；如果 newpath 是软链接，则会将其移除、被覆盖
  5. 如果 oldpath 指代文件而非目录，那么就不能将 newpath 指定为一个目录的路径名；要想重命名一个文件到某一个目录下，newpath 必须包含新的文件名
  6. 如果 oldpath 指代为一个目录，那么 newpath 要么不存在，要么必须指定为一个空目录
  7. oldpath 和 newpath 所指代的文件必须位于同一文件系统（跨文件系统返回 EXDEV，需要先拷贝再删除）
  8. 不能对 .（当前目录）和 ..（上一级目录）进行重命名
