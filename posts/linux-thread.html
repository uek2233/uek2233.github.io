线程概述

线程是什么

当一个程序启动时，就有一个进程被操作系统创建，与此同时一个线程也立刻开始运行，这个线程通常叫做主线程（Main Thread），因为它是程序一开始时就运行的线程。应用程序都是以 main() 作为入口开始运行的，所以 main() 函数就是主线程的入口函数，main() 所执行的任务就是主线程需要执行的任务。

其它线程通常由主线程调用 pthread_create() 创建，创建出来的新线程就是主线程的子线程。

  • 同一进程中的多个线程共享该进程中的全部系统资源（代码段、数据段、堆、打开的文件描述符、信号处理动作……）
  • 每个线程又有自己私有的东西：
    • 自己的调用栈（call stack，也叫线程栈）
    • 自己的寄存器环境（register context，含程序计数器 PC、栈指针 SP）
    • 自己的线程本地存储（thread-local storage）
    • 自己的 errno 副本（为了与使用 errno 的函数兼容）
    • 自己的信号屏蔽字、取消性状态/类型

主线程的两个典型职责：

  • 创建其它新的线程
  • 回收各个子线程（pthread_join()）

线程的特点

  • 线程不单独存在，而是包含在进程中（没有进程就没有线程）
  • 线程是参与系统调度的基本单位（内核真正调度的是线程，不是进程）
  • 可并发执行：同一进程的多个线程之间可并发执行，宏观上实现"同时运行"的效果
  • 共享进程资源：地址空间、文件描述符、信号处理动作等

线程与进程的区别

对比项 进程 线程
定位 资源分配的基本单位 调度/执行的基本单位
地址空间 各自独立 同一进程内所有线程共享
切换开销 大（要切换页表、刷新 TLB 等） 小（同一地址空间，只需切换寄存器和栈）
通信方式 需要 IPC（管道、共享内存、消息队列……） 直接读写共享变量（但要注意同步）
创建开销 大（要复制/共享资源） 小
多核利用 多进程也能利用多核 多线程在多核上更有优势
崩溃影响 一个进程崩溃一般不影响其它进程 一个线程崩溃（如段错误）会导致整个进程退出

一句话：真正被运行的是进程中的线程，进程本身不能"运行"。

多进程 vs 多线程

多进程编程的劣势：

  • 进程间切换开销大
  • 进程间通信较为麻烦

多线程编程的优势：

  • 同一进程的多个线程间切换开销比较小
  • 同一进程的多个线程间通信容易（共享地址空间，直接读写变量）
  • 多线程在多核处理器上更有优势

多线程编程的代价：

多线程编程难度高，对程序员的编程功底要求比较高，因为在多线程环境下需要考虑很多问题，例如线程安全问题、信号处理的问题等。

并发与并行

  • 串行：一件事、一件事接着做
  • 并发（Concurrency）：交替做不同的事，强调时分复用。与串行的区别在于：不必等上一个任务完成才做下一个，可以打断当前任务、切去执行另一个任务
  • 并行（Parallelism）：同时做不同的事，指的是"可以并排/并列执行多个任务"，这样的系统通常有多个执行单元（多条指令流水线、多个核心）

并行运行并不要求多个任务同时开始、同时结束，只要求在某一个时间段上存在多个任务被多个执行单元同时运行着。

并行运行情况下的多个执行单元，每一个执行单元自身同样也可以以并发方式运行（例如 8 核处理器，每个核上还可以交替跑多个线程）。

单核、多核与内核调度

  • 单核处理器：只有一个执行单元，同时只能执行一条指令，只能采用并发方式运行系统中的线程（例如 I.MX6U 硬件平台，单核 Cortex-A7 SoC）
  • 多核处理器：有多个执行单元，可以并行执行多条指令（8 核处理器可以并行执行 8 条不同的指令），同时每个核上依旧并发调度

内核实现了调度算法，用于控制系统中所有线程的调度。简单来说，系统中所有参与调度的线程会加入到系统的调度队列中，由内核控制：每一个线程执行一段时间后，由系统调度切换执行调度队列中的下一个线程，依次进行。

补充：Linux 上内核调度的对象是线程（task），所谓"进程调度"实际上是"该进程中某个线程被调度"，所以单核并发、多核并行的关系是： 并发是逻辑上同时（时分复用）；并行是物理上同时（真多核）。并发是并行的必要不充分条件。

线程 ID

进程 ID 在整个系统中是唯一的，但线程 ID 不同：线程 ID 只有在它所属的进程上下文中才有意义（同一进程内唯一，不同进程里可以出现相同的值）。

线程 ID 的作用：

  • pthread_cancel()、pthread_detach()、pthread_join() 等函数，都是利用线程 ID 来标识要操作的目标线程
  • 以特定线程的线程 ID 作为动态数据结构的标签，既可以用来标识整个数据结构的创建者或属主线程，又可以确定随后对该数据结构执行操作的具体线程

终止线程

终止线程运行的方法：

  • 线程的 start 函数执行 return 语句并返回指定值，返回值就是线程的退出码
  • 线程调用 pthread_exit() 函数
  • 调用 pthread_cancel() 取消线程（严格说是"提出请求"，见"取消线程"一节）

作用:: 终止调用它的那个线程（而不是整个进程），并让该线程的返回值变得可被 pthread_join() 获取。

用法：

参数：retval：线程的"返回值"，将被 pthread_join() 的第二个参数接收；不关心时可传 NULL

注意事项：

  • retval 所指向的内容不应分配在线程栈中：线程终止后，无法确定线程栈的内容是否还有效。同理，也不应在线程栈中分配线程 start 函数的返回值。需要返回数据时用全局/静态变量或 malloc 出来的堆内存
  • 如果主线程调用了 pthread_exit()，那么主线程也会终止，但其它线程依然正常运行，直到进程中的所有线程终止才会使得进程终止

  • 注意区分：pthread_exit() 只影响调用线程；exit()/_exit() 会让整个进程退出

pthread_join() — 等待并回收线程

作用:: 阻塞等待指定的可汇合（joinable）线程终止，并回收其资源；同时可以取出目标线程的终止状态。

用法：

参数：

  • thread：要等待的目标线程 ID
  • retval：输出参数。目标线程 return / pthread_exit() 的返回值会复制到 *retval 所指向的内存区域；如果目标线程是被 pthread_cancel() 取消的，则将 PTHREAD_CANCELED（一个值为 (void *) -1 的宏）放在 *retval 中。如果对目标线程的终止状态不感兴趣，可将参数 retval 设置为 NULL

返回值：成功返回 0；失败返回错误码（ESRCH 无此线程 / EINVAL 线程不可汇合（已分离）或已有线程在 join 它 / EDEADLK 检测到死锁，如自己 join 自己）

注意事项：

  • pthread_join() 以阻塞的形式等待指定的线程终止；如果该线程已经终止，则 pthread_join() 立刻返回
  • 如果多个线程同时尝试调用 pthread_join() 等待同一个指定线程的终止，那么结果将是不确定的。要保证只有一个线程去 join
  • 线程是可汇合还是分离，由创建时的 detachstate 属性或运行期的 pthread_detach() 决定；分离线程 join 会返回 EINVAL
  • 不能 join 自己（会死锁，Linux 上返回 EDEADLK）

僵尸线程：

如果线程终止后，其它线程没有调用 pthread_join() 函数来回收该线程，那么该线程将变成僵尸线程，与僵尸进程的概念相类似；僵尸线程除了浪费系统资源外，若僵尸线程积累过多，那么会导致应用程序无法创建新的线程。

如果进程中存在着僵尸线程并未得到回收，当进程终止之后，进程会被其父进程回收，所以僵尸线程同样也会被回收。

补充两点：

  • 只有可汇合线程才会变僵尸；分离线程终止后由系统自动回收资源，不会变僵尸
  • 僵尸线程占的主要是内核里的 task 结构和线程 ID（TID），而不是用户态的栈（栈在退出时已释放）。所以僵尸线程的危害是耗尽线程 ID / 进程表项，最终 pthread_create() 报 EAGAIN、fork() 报 EAGAIN

pthread_join() 与 waitpid() 的区别：

  • 调用者范围不同：进程中的任意线程均可调用 pthread_join() 来等待另一个线程的终止。譬如，如果线程 A 创建了线程 B，线程 B 再创建线程 C，那么线程 A 可以调用 pthread_join() 等待线程 C 的终止，线程 C 也可以调用 pthread_join() 等待线程 A 的终止；这与进程间的层次关系不同——父进程如果用 fork() 创建了子进程，那么它也是唯一能够对子进程调用 wait() 的进程，线程之间不存在这样的层次限制
  • 能否非阻塞：不能以非阻塞的方式调用 pthread_join()。对于进程，调用 waitpid() 既可以实现阻塞方式等待、也可以实现非阻塞方式等待（WNOHANG）。想在多线程里"非阻塞地探测线程是否结束"，只能自己用条件变量/标志位实现
对比项 waitpid()（进程） pthread_join()（线程）
谁能调用 只有父进程 同进程内任意线程
指定对象 子进程 PID 任意可汇合线程 ID
非阻塞 支持 WNOHANG 不支持，只能阻塞
状态编码 status + WIFEXITED 等宏 void * 返回值，取消则为 PTHREAD_CANCELED

分离线程

当线程终止时，其它线程可以通过调用 pthread_join() 获取其返回状态、回收线程资源。但有时程序员并不关心线程的返回状态，只是希望系统在线程终止时能够自动回收线程资源并将其移除。在这种情况下，可以调用 pthread_detach() 将指定线程进行分离，也就是分离线程。

一旦线程处于分离状态：

  • 不能再使用 pthread_join() 来获取其终止状态（会返回 EINVAL）
  • 此过程不可逆，一旦处于分离状态之后便不能再恢复到之前的状态
  • 处于分离状态的线程，当其终止后能够自动回收线程资源（不会变成僵尸线程）

线程栈属性

每个线程都有自己的栈空间，pthread_attr_t 数据结构中定义了栈的起始地址以及栈大小。调用 pthread_attr_getstack() 可以获取这些信息，pthread_attr_setstack() 对栈起始地址和栈大小进行设置。

在 Linux 下，创建一个线程时如果不指定栈地址，系统会自动 mmap 一块内存当作该线程的栈，这块内存有两个特殊的页：一个保护页（guard page，用来检测栈溢出）——所以实际映射比栈大小多一页。

线程安全

可重入函数

进程中执行流的数量除了与线程有关之外，与信号处理也有关联。因为信号是异步的，进程可能会在其运行过程中的任何时间点收到信号，进而跳转、执行信号处理函数，从而在一个单线程进程（包含信号处理）中形成了两条（即主程序和信号处理函数）独立的执行流。

如果一个函数被同一进程的多个不同的执行流同时调用，每次函数调用总是能产生正确的结果（或者叫产生预期的结果），把这样的函数就称为可重入函数。

函数被多个执行流同时调用的两种情况：

  • 在一个含有信号处理的程序当中，主程序正执行函数 func()，此时进程接收到信号，主程序被打断，跳转到信号处理函数中执行，信号处理函数中也调用了 func()
  • 在多线程环境下，多个线程并发调用同一个函数

可重入函数分为两类：

  • 绝对的可重入函数：所谓"绝对"，指的是该函数不管如何调用，都能断言它是可重入的，都能得到预期的结果。
    • 函数内所使用到的变量均为局部变量，换句话说，该函数内的操作的内存地址均为本地栈地址
    • 函数参数和返回值均是值类型
    • 函数内调用的其它函数也均是绝对可重入函数
  • 带条件的可重入函数：指的是在满足某个/某些条件的情况下，可以断言该函数是可重入的，不管怎么调用都能得到预期的结果。
    • 例如："对全局变量 glob 进行写操作"——只有在"调用者保护了 glob"（比如加锁、或屏蔽信号）这个前提下才是可重入的

很多 C 库函数有两个版本：可重入版本和不可重入版本。可重入版本函数其名称后面加上了 _r，用于表明该函数是一个可重入函数；而不可重入版本函数其名称后面没有 _r（例如 strtok() 与 strtok_r()、localtime() 与 localtime_r()、gethostbyname() 与 gethostbyname_r()）。

用 man 判断：

  • man 3 <函数> 可以查看函数的安全属性，有些函数显示 MT-Unsafe，而有些函数显示的却是 MT-Safe
  • MT 指的是 multithreaded（多线程），所以 MT-Unsafe 就是多线程不安全，MT-Safe 指的是多线程安全
  • MT-Safe 标签后面可能会携带诸如 env 或 locale 之类的标签，这其实就表示该函数需要在满足 env 或 locale 条件的情况下才是可重入函数；如果是绝对可重入函数，MT-Safe 标签后面不会携带任何标签，譬如数学库函数 sqrt

线程安全函数

一个函数被多个线程（其实也是多个执行流，但是不包括由信号处理函数所产生的执行流）同时调用时，它总会一直产生正确的结果，把这样的函数称为线程安全函数。

关键结论：

  • 线程安全函数包括可重入函数；可重入函数是线程安全函数的一个真子集——也就是说可重入函数一定是线程安全函数，但线程安全函数不一定是可重入函数
  • 可重入函数只是单纯从语言语法角度分析它的可重入性质，不涉及到一些具体的实现机制（譬如线程同步技术）——这是判断可重入函数和线程安全函数的区别
  • 判断一个函数是否为线程安全函数：该函数被多个线程同时调用是否总能产生正确的结果，如果每次都能产生预期的结果，则表示该函数是一个线程安全函数
  • 判断一个函数是否为可重入函数：从语言语法角度分析，该函数被多个执行流（含信号处理产生的执行流）同时调用是否总能产生正确的结果，如果每次都能产生预期的结果，则表示该函数是一个可重入函数

典型的"线程安全但不可重入"的函数：内部用了互斥锁保护共享数据。多个线程调用它没问题（线程安全），但如果信号处理函数在某个线程持锁时打断了它、又在处理函数里调用同一个函数，就会自己把自己锁死（不可重入）。

线程私有数据的意义

线程特有数据（TSD, Thread-Specific Data）

什么时候需要 TSD：函数要返回"一块还能继续用的缓冲区指针"，且多线程各自一份。

信号如何映射到线程

  • 信号的系统默认行为是属于进程层：每一个信号都有其对应的系统默认动作，当进程中的任一线程收到任何一个未经处理（忽略或捕获）的信号时，会执行该信号的默认操作，信号的默认操作通常是停止或终止进程
  • 信号处理函数属于进程层面：进程中的所有线程共享程序中所注册的信号处理函数
  • 信号的发送既可针对整个进程，也可针对某个特定的线程。在满足以下三个条件中的任意一个时，信号的发送针对的是某个线程：
    • 由于某个线程自身执行了错误代码而引发的硬件异常信号（例如：线程踩内存引发 SIGSEGV、除以 0 引发 SIGFPE、执行非法指令引发 SIGILL）
    • 当线程试图对已断开的管道进行写操作时所产生的 SIGPIPE 信号
    • 由函数 pthread_kill() 或 pthread_sigqueue() 所发出的信号，这些函数允许线程向同一进程下的其它线程发送一个指定的信号，选择一个"没有屏蔽该信号"的线程来执行信号处理函数
  • 其它机制产生的信号均属于进程层面，譬如其它进程调用 kill() 或 sigqueue() 所发送的信号；用户在终端按下 Ctrl+C、Ctrl+\、Ctrl+Z 向前台进程发送的 SIGINT、SIGQUIT 以及 SIGTSTP 信号
  • 当一个多线程进程接收到一个信号时，且该信号绑定了信号处理函数时，内核会任选一个线程来接收这个信号，意味着由该线程接收信号并调用信号处理函数对其进行处理，并不是每个线程都会接收到该信号并调用信号处理函数
  • 信号掩码其实是属于线程层面的：在多线程环境下，各个线程可以调用 pthread_sigmask() 函数来设置它们各自的信号掩码，譬如设置线程可以接收哪些信号、不接收哪些信号，各线程可独立阻止或放行各种信号
  • 未决信号与线程掩码相关：sigpending() 返回的是"针对整个进程所挂起的信号"与"针对调用线程所挂起的信号"的并集

多线程信号处理的重大陷阱

在多线程中乱用信号处理函数会导致极其难以调试的 Bug：

  • 处理函数是进程共享的：虽然执行函数的可能只是某一个线程，但信号的处理动作（通过 sigaction 或 signal 注册的函数）在整个进程内是唯一的
  • 异步信号安全（Async-Signal-Safe）：执行处理函数的线程会被无条件强行中断，去执行处理函数。如果这个线程恰好在持有某个锁（比如 printf 内部的 stdout 锁），而你的信号处理函数里又调用了 printf，就会导致死锁
  • 数据竞争：处理函数可能打断任意线程的任意指令，如果它访问了该线程正在修改的全局数据结构，就会读到中间状态

解决方法：专用信号处理线程

推荐做法分三步（也是 POSIX 社区的标准建议）：

  1. 全员屏蔽：在 main 函数的最开始、创建任何子线程之前，调用 pthread_sigmask() 屏蔽所有可能异步到达的信号（如 SIGINT, SIGTERM）。这样后续创建的所有子线程都会继承这个屏蔽字
  2. 专职线程：专门创建一个独立的子线程，在这个线程里调用 sigwait() 或 sigwaitinfo() 函数，死循环进入阻塞
  3. 同步化处理：当外部信号到来时，因为只有这个专职线程在用 sigwait() 显式等待，内核一定会把信号给它。更重要的是，sigwait() 会让信号处理变成同步逻辑，你可以在这个线程里安全地调用任何锁、printf 或进行优雅退出的清理工作，彻底避免了异步信号安全的死锁陷阱

这个模型还有一个附带好处：多个信号源、信号与"业务事件"可以统一成"从队列里取事件"的模型，主循环逻辑变得非常干净。

作用:: 设置调用线程的信号掩码（阻塞 / 解除阻塞 / 直接设置）。多线程程序中应当使用本函数而不是 sigprocmask()。

用法：

参数：

作用:: 以同步方式等待信号集中的信号，信号到来前一直阻塞。

用法：

异步信号安全函数

应用程序中涉及信号处理函数时必须要非常小心，因为信号处理函数可能会在程序执行的任意时间点被调用，从而打断主程序。

线程安全函数不能在信号处理函数中被调用，否则就不能保证它一定是安全的。所以就出现了异步信号安全函数。

异步信号安全函数指的是可以在信号处理函数中可以被安全调用的线程安全函数，所以它比线程安全函数的要求更为严格。

  • 可重入函数一定是异步信号安全函数
  • 而线程安全函数则不一定是异步信号安全函数（因为线程安全函数可能靠锁实现，而锁在"信号打断 + 同线程重入"场景下会死锁）

经典死锁例子：

设线程 1 正在执行函数 func，刚刚获得锁（也就是刚刚对互斥锁上锁），而这时进程收到信号，并分派给线程 1 处理，线程 1 接着跳转去执行信号处理函数。不巧的是，信号处理函数中也调用了 func() 函数，同样它也去获取锁，由于此时锁处于锁住状态，所以信号处理函数中调用 func() 获取锁将会陷入休眠、等待锁的释放。这时线程 1 就会陷入死锁状态，线程 1 无法执行，锁无法释放；如果其它线程也调用 func()，那它们也会陷入休眠，如此将会导致整个程序陷入死锁。

根本原因：

  • 信号是异步的，信号可能会在任何时间点中断主程序的运行，跳转到信号处理函数处执行，从而形成一个新的执行流——而这个新执行流和被打断的执行流是同一个线程，锁的"属主"概念在这里失效（对互斥锁来说，同一个线程再次加锁就是死锁）

三者中，可重入函数的要求是最严格的，所以通常会总结为："可重入函数一定是线程安全函数，也一定是异步信号安全函数"。

编写安全的信号处理函数，需要做到以下几点：

  • 首先确保信号处理函数本身的代码是可重入的，且只能调用异步信号安全函数

补充：线程编程实战要点

pthread_t 不可直接比较或打印

  • pthread_t 是不透明类型：glibc 上它就是 unsigned long，但别的系统可能是结构体或指针
  • 比较：一律用 pthread_equal(t1, t2)，不要用 ==

多线程与 fork

  • 在多线程进程中调用 fork()，子进程只包含调用 fork 的那个线程的副本，其它线程在子进程中不存在（这是 POSIX 的明确规定，也是为什么"fork 后马上 exec"是最安全的用法）
  • 更危险的是：子进程里的互斥锁状态被继承。如果 fork 那一刻某个锁正被别的线程持有，那么子进程里这个锁将永远处于加锁状态，且没有任何线程会释放它 → 死锁
  • 因此 POSIX 规定：多线程进程 fork 之后、exec 之前，子进程只应调用异步信号安全函数（malloc、printf 都不安全！）
  • 解决办法：用 pthread_atfork(prepare, parent, child) 注册三个回调，在 fork 前加锁、fork 后在父子进程各自解锁
  • 参考：Processe/src/fork1.cc、Processe/src/fork2.cc（单线程语境下的 fork），多线程语境下的这条坑在 进程基础 笔记里也有呼应

PTHREAD_CANCELED 回收线程 被取消线程的终止状态标记（(void*)-1）
pthread_cancel() 取消线程 向目标线程发出取消请求（立即返回，不等待）
pthread_setcancelstate() 取消线程 设置"能否被取消"（ENABLE / DISABLE）
pthread_setcanceltype() 取消线程 设置"何时被取消"（DEFERRED / ASYNCHRONOUS）
pthread_testcancel() 取消线程 手工产生一个取消点
pthread_detach() 分离线程 标记线程为分离态，退出时系统自动回收
pthread_cleanup_push() 清理处理函数 压入清理函数（pthread_exit/取消/pop(非0) 时执行）
pthread_cleanup_pop() 清理处理函数 弹出栈顶清理函数，参数非 0 则同时执行
pthread_attr_init() 线程属性 用默认值初始化线程属性对象
pthread_attr_destroy() 线程属性 销毁线程属性对象
pthread_attr_setstacksize() / pthread_attr_getstacksize() 线程属性 设置 / 获取线程栈大小（默认 8MB）
pthread_attr_setstack() / pthread_attr_getstack() 线程属性 设置 / 获取栈的起始地址与大小
pthread_attr_setdetachstate() / pthread_attr_getdetachstate() 线程属性 设置 / 获取创建时的分离状态
pthread_once() 线程安全 保证初始化函数在进程内只执行一次
pthread_key_create() 线程安全 创建线程私有数据的键（key）
pthread_setspecific() 线程安全 把本线程的私有数据绑定到 key
pthread_getspecific() 线程安全 取出本线程绑定在 key 上的私有数据
pthread_key_delete() 线程安全 删除 key（不触发析构、不释放数据）
__thread / thread_local 线程安全 线程局部存储关键字，每线程一份变量副本
pthread_sigmask() 线程与信号 设置调用线程的信号掩码（替代 sigprocmask）
sigwait() 线程与信号 同步等待信号（专职信号线程核心）
sigwaitinfo() 线程与信号 同步等待信号并取出 siginfo_t（含伴随数据）
pthread_kill() 线程与信号 向同进程内指定线程发送信号（sig=0 探测存活）
pthread_sigqueue() 线程与信号 向指定线程发送带伴随数据的信号
pthread_setname_np() 实战要点 给线程起名字，便于调试
