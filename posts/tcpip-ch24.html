总结

小结:: 本章应用前面学到的所有网络编程知识，动手实现一个简单的 HTTP 服务器。核心在于理解 HTTP 协议的请求/响应格式，以及如何通过套接字编程解析 HTTP 请求并返回正确的 HTTP 响应。这是一个综合实战章节，将 socket、I/O、多线程等技术融会贯通。

HTTP 协议基础

什么是 HTTP

HTTP（HyperText Transfer Protocol，超文本传输协议）是 Web 通信的基础协议。它是一个无状态、基于请求/响应模型的文本协议，默认使用 80 端口。

HTTP 请求格式

客户端发送给服务器的 HTTP 请求：

请求行的格式：

部分 说明
METHOD 请求方法：GET、POST、PUT、DELETE 等
URI 请求的资源路径，如 /index.html、/image/logo.png
HTTP_VERSION HTTP 版本，如 HTTP/1.0、HTTP/1.1

常见请求方法：

方法 含义
GET 请求资源（最常用）
POST 提交数据（表单等）
HEAD 只请求响应头，不获取响应体

状态码 含义

4xx 客户端错误
400 Bad Request 请求格式错误
404 Not Found 资源不存在
5xx 服务器错误
500 Internal Server Error 服务器内部错误

HTTP 服务器的优化方向

优化 说明
线程池 限制并发线程数，避免线程创建开销
epoll 事件驱动 使用 epoll 管理大量连接，避免每个连接一个线程
缓存 缓存常用文件的内容，避免重复磁盘 I/O
Keep-Alive HTTP/1.1 的持久连接，减少连接建立/关闭开销
零拷贝 使用 sendfile() 系统调用，避免用户态/内核态数据拷贝

本章要点

概念 说明
HTTP 请求格式 请求行 + 头部 + 空行 + 消息体
HTTP 响应格式 状态行 + 头部 + 空行 + 消息体
状态码 200 OK、301、404 Not Found、500 等
MIME 类型 Content-Type 告诉浏览器如何解析响应体
文件服务 读取服务器文件返回给客户端
并发处理 多线程/事件驱动处理多个请求

灵魂总结

HTTP 服务器是前面所有网络编程知识的综合应用：套接字创建与绑定（第1-3章）、I/O 读写（第5章）、并发处理（第10/18章）、半关闭（第7章），以及标准 I/O（第15章）、流分离（第16章）。

理解了 HTTP 协议的精髓——纯文本的请求/响应模型，你就能自己动手实现一个 Web 服务器。从最简单的单线程版本开始，逐步加入并发、缓存、日志等功能，就是一个小型 Nginx 的雏形！🌐
