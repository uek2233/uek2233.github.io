字符串处理

学习 Linux 应用编程时整理的笔记，涵盖：字符串的输入/输出、长度计算、拷贝、拼接、比较、查找、与数字互转，以及 POSIX 正则表达式。

阅读建议：先掌握「怎么进、怎么出」（输入/输出），再熟悉「多长、怎么复制拼接」（长度/拷贝/拼接），然后是「怎么比、怎么找」（比较/查找），最后是「怎么转」（数字互转与正则）。

字符串输出

函数 作用 成功返回 失败返回
puts() 输出字符串到标准输出，末尾自动换行 非负值（0） EOF
putchar() 输出单个字符到标准输出 写入的字符 EOF
fputs() 输出字符串到指定文件流，不自动换行 非负值（0） EOF
fputc() 输出单个字符到指定文件流 写入的字符 EOF

💡 输出函数可以按「对象（字符串/字符）× 目的地（标准输出/指定流）」组成 2×2 矩阵，4 个函数两两对应。

puts() — 输出字符串到标准输出

作用:: 将字符串输出到标准输出设备，输出完字符串内容后自动输出一个换行符 '\n'（相当于把字符串结尾的 '\0' 转成了 '\n'）。仅限于输出字符串。

用法：

  • s：要输出的字符串（必须以 '\0' 结尾）

注意事项：

  1. puts() 输出后自动追加换行符，等价于 printf("%s\n", s)
  2. 只能输出字符串，不能带格式控制；需要格式化时用 printf()
  3. 与 fputs(s, stdout) 的区别：fputs() 不会自动追加换行

putchar() — 输出单个字符到标准输出

作用:: 将一个字符输出到标准输出设备，等价于 fputc(c, stdout)。只能输出单个字符。

用法：

  • c：要输出的字符（int 类型，实际按 unsigned char 处理）

注意事项：

  1. 参数虽然是 int，但实际写入的是 unsigned char 转换后的字符
  2. 输出单个字符用 putchar()，输出字符串用 puts() 或 printf("%s", ...)

fputs() — 输出字符串到指定流

作用:: 与 puts() 类似，但可以指定输出到哪个文件流（文件、标准输出、标准错误等），不会自动追加换行符。

用法：

  • s：要输出的字符串
  • stream：目标文件流，如 stdout、stderr 或 fopen() 打开的文件

注意事项：

  1. fputs() 不自动加换行，需要换行要手动加 '\n'（puts() 自动加）
  2. 写文件时若文件按文本模式打开，换行符会被转换为 \r\n（Windows）；Linux 下无此转换

fputc() — 输出单个字符到指定流

作用:: 与 putchar() 类似，但可以指定输出到哪个文件流。

用法：

  • c：要输出的字符（int 类型）
  • stream：目标文件流

注意事项：

  1. 写入失败时返回 EOF
  2. putchar(c) 等价于 fputc(c, stdout)

字符串输入

函数 作用 成功返回 失败返回
gets() 从标准输入读取一行字符串（⚠️ 已废弃，勿用） 缓冲区指针 s NULL
fgets() 从指定流读取一行字符串，可限制最大长度（✅ 推荐） 缓冲区指针 s NULL（末尾或出错）
getchar() 从标准输入读取一个字符 读取的字符（int） EOF
fgetc() 从指定流读取一个字符 读取的字符（int） EOF

💡 输入函数的核心要点：缓冲区溢出防护。gets() 无法限制长度是它被废弃的根本原因，一律用 fgets() 替代。

gets() — 从标准输入读取字符串（⚠️ 已废弃）

作用:: 从标准输入设备（键盘）中获取用户输入的字符串，以回车换行符作为分隔符，将 '\n' 替换为字符串结束符 '\0'。

用法：

  • s：存放输入字符串的缓冲区

注意事项：

  1. 没有长度限制参数，无法防止缓冲区溢出——这是著名的安全漏洞来源，C11 标准已将其移除，生产代码严禁使用，一律用 fgets() 替代
  2. gets() 会将回车换行符从输入缓冲区中取出并丢弃，缓冲区不会遗留 '\n'
  3. 与 scanf("%s", ...) 的区别：
    • scanf 以空格、换行、TAB 等空白字符作为字符串分隔符，遇到就停止读取，这些字符不会进入字符串；gets() 将空格和 TAB 视为字符串内容的一部分，仅以回车作为分隔符
    • scanf() 不会把分隔符从输入缓冲区中读走，读完后缓冲区里还残留着分隔符；gets() 会把回车取走并丢弃

fgets() — 从指定流读取字符串（✅ 推荐）

作用:: 从指定的文件流（标准输入或普通文件）中读取一行字符串，可以设置最大读取字符数，防止缓冲区溢出。

用法：

  • s：存放读取内容的缓冲区
  • size：最多读取 size - 1 个字符（留一个位置给 '\0'）
  • stream：数据来源，如 stdin 或 fopen() 打开的文件

注意事项：

  1. 与 gets() 的区别：
    • gets() 只能从标准输入读取；fgets() 既可以从标准输入、也可以从普通文件读取
    • fgets() 可以设置最大字符数，gets() 不能
    • gets() 会把 '\n' 读出来并丢弃；fgets() 也会把 '\n' 读出来，但不丢弃，而是作为字符串的一部分保留（放在 '\0' 前面）
  2. 如果这一行长度超过 size - 1，fgets() 只读前 size - 1 个字符，剩下的留在缓冲区中，下次调用继续读（实际生产中长行需要配合循环处理）
  3. 读到 '\n' 就停止，因此 fgets() 适合按行读取
  4. 读取到的字符串末尾总会添加 '\0'
  5. 返回 NULL 时用 feof() / ferror() 区分是「读到了末尾」还是「读取出错」

getchar() — 从标准输入读取一个字符

作用:: 从标准输入设备读取一个字符，包括空格、TAB、换行回车符等，等价于 fgetc(stdin)。

用法：

注意事项：

  1. 返回值是 int 而不是 char——因为要能表示 EOF（-1），用 char 接收会截断
  2. 终端输入是行缓冲的：用户按下回车后，getchar() 才会真正从缓冲区取数据
  3. 读取一个字符后，缓冲区中剩余的字符（包括回车）还在，需要时可用循环清空

fgetc() — 从指定流读取一个字符

作用:: 从指定的文件流中读取一个字符，等价于 getc(stream)。

用法：

  • stream：数据来源文件流

注意事项：

  1. 返回值同样是 int，用 EOF 判断读取结束或出错
  2. 返回 EOF 后，用 feof() / ferror() 区分「到文件末尾」还是「读取出错」

字符串长度

函数 作用 返回值
strlen() 计算字符串长度（不含结尾的 '\0'） size_t 类型长度

strlen() — 计算字符串长度

作用:: 计算字符串的长度，即从起始位置到第一个 '\0' 之间的字符个数（不包括 '\0' 本身）。字符串必须包含结束字符 '\0'，否则行为未定义。

用法：

  • s：字符串首地址，必须以 '\0' 结尾

注意事项：

  1. 返回类型是 size_t（无符号），不要与负数直接比较，也不要相减后判断正负（会变成很大的无符号数）
  2. 若字符串没有 '\0' 结尾（如 strncpy() 截断导致的「非 C 字符串」），strlen() 会一直往后扫描直到遇到内存中的 '\0'，可能越界——这是常见 bug
  3. 时间复杂度为 O(n)，会遍历整个字符串；循环里反复调用 strlen() 会低效，可先把长度存起来

sizeof 与 strlen 的区别

对比项 sizeof strlen()
本质 C 语言内置的操作符/关键字 C 语言库函数
计算时机 编译时由编译器算出结果 运行时才计算
作用对象 数据类型的大小或变量占用内存的大小 只能作用于以 '\0' 结尾的字符串
计算结果 变量/类型所占的内存字节数 字符串的实际长度（不含 '\0'）
对数组 返回整个数组的字节数（含 '\0'） 返回 '\0' 前的字符个数

📌 注意：sizeof 作用于指针时只返回指针本身的大小（如 8 字节），而不是它指向的字符串长度；strlen 作用于指针时则会遍历指针指向的字符串。

字符串拷贝

函数 作用 成功返回 失败返回
strcpy() 把源字符串（含 '\0'）复制到目标缓冲区 目标指针 dest N/A（不检查）
strncpy() 复制指定数量字符到目标缓冲区 目标指针 dest N/A（不检查）

💡 拷贝函数都不检查目标缓冲区大小，缓冲区溢出风险由调用者负责。strncpy() 并不能完全解决这个问题，还引入了「可能不带 '\0'」的新坑。

strcpy() — 复制字符串

作用:: 将 src 指向的字符串（包括结束字符 '\0'）复制到 dest 指向的缓冲区中。src 必须包含结束字符 '\0'。

用法：

  • dest：目标缓冲区，必须足够大以容纳 src 全部内容（含 '\0'）
  • src：源字符串，必须以 '\0' 结尾

注意事项：

  1. 不会检查 dest 的空间是否足够，dest 太小会导致缓冲区溢出（buffer overflow），这是常见安全漏洞
  2. src 必须是以 '\0' 结尾的字符串，否则会越界复制
  3. dest 和 src 不能重叠（重叠区域行为未定义），重叠场景用 memmove()

strncpy() — 复制指定数量的字符

作用:: 与 strcpy() 类似，但可以指定从源字符串 src 复制到目标缓冲区 dest 的字符数量 n。

用法：

  • dest：目标缓冲区
  • src：源字符串
  • n：最多复制的字符数

注意事项（重点！）：

  1. 如果 src 长度 >= n，只复制 n 个字符，不会自动补 '\0'——dest 很可能不是以 '\0' 结尾的「非 C 字符串」，后续调用 strlen() / strcpy() / printf("%s") 都会出问题
  2. 如果 src 长度 < n，复制完 src 后剩余部分会用 '\0' 填充（零填充）
  3. 安全用法：复制后手动补一个 '\0'（见下方示例），保证字符串始终以 '\0' 结尾

字符串拼接

函数 作用 成功返回 失败返回
strcat() 把源字符串追加到目标字符串末尾 目标指针 dest N/A（不检查）
strncat() 追加指定数量字符到目标字符串末尾 目标指针 dest N/A（不检查）

💡 拼接的本质是「找到 dest 的 '\0'，从那里开始覆盖写入」。两个函数都不检查目标空间；strncat() 限制的是追加的数量，而不是总空间。

strcat() — 拼接字符串

作用:: 把 src 所指向的字符串追加到 dest 所指向的字符串末尾。dest 末尾的 '\0' 结束字符会被覆盖，src 末尾的结束字符 '\0' 会一起被复制过去，最终合并后的字符串只有一个 '\0'。

用法：

  • dest：目标字符串，必须有足够的剩余空间（strlen(dest) + strlen(src) + 1）
  • src：要追加的源字符串

注意事项：

  1. 不检查空间：dest 剩余空间必须 >= strlen(src) + 1，否则缓冲区溢出
  2. dest 必须是以 '\0' 结尾的字符串，strcat() 从 dest 的 '\0' 处开始追加
  3. dest 与 src 不能重叠

strncat() — 拼接指定数量的字符

作用:: 与 strcat() 作用相似，但可以指定最多从 src 追加 n 个字符到目标字符串末尾，并在追加完成后自动添加结束字符 '\0'。

用法：

  • dest：目标字符串
  • src：源字符串
  • n：最多追加的字符数（不含 '\0'）

注意事项：

  1. 参数 n 是「最多追加几个字符」，追加后总会在末尾补 '\0'，所以 dest 至少需要 strlen(dest) + n + 1 字节空间
  2. 与 strncpy() 不同：strncat() 不会用 '\0' 填充剩余空间，也不会产生非 C 字符串
  3. 若 src 长度不足 n，则复制到 src 的 '\0' 为止

字符串比较

函数 作用 返回值
strcmp() 逐字符比较两个字符串（按 ASCII 码） <0 / 0 / >0
strncmp() 只比较两个字符串的前 n 个字符 <0 / 0 / >0

strcmp() — 比较两个字符串

作用:: 比较两个字符串的大小，逐字符比较对应的 ASCII 码值，直到出现差异或遇到 '\0'。

用法：

  • s1、s2：要比较的两个字符串

注意事项：

  1. 返回值是「小于/等于/大于 0」，不要依赖具体数值（有的平台返回差值，有的返回 -1/0/1）
  2. 比较的是字符的 ASCII 码值，'A'（65）< 'a'（97），区分大小写；需要忽略大小写用 strcasecmp()（Linux 下可用）
  3. 不要用 == 直接比较两个字符串内容 == 比较的是指针地址，不是内容

strncmp() — 比较前 n 个字符

作用:: 与 strcmp() 类似，但最多只比较前 n 个字符，适合比较字符串前缀。

用法：

  • s1、s2：要比较的字符串
  • n：最多比较的字符数

注意事项：

  1. 比较到 n 个字符或遇到 '\0' 就停止
  2. 常用于判断前缀：如判断字符串是否以 "http://" 开头
  3. 注意 n 不能超过字符串实际长度，否则会越界读取

字符串查找

函数 作用 成功返回 失败返回
strchr() 在字符串中查找第一个指定字符 该字符位置指针 NULL
strrchr() 在字符串中查找最后一个指定字符（从右往左） 该字符位置指针 NULL
strstr() 在字符串中查找第一次出现的子字符串 子串位置指针 NULL

strchr() — 查找第一个指定字符

作用:: 在给定字符串 s 中查找字符 c 第一次出现的位置，返回指向该位置的指针。

用法：

  • s：被查找的字符串
  • c：要查找的字符（int 类型，实际按 char 处理）

注意事项：

  1. 参数 c 是 int，但会先转换为 char 再参与匹配
  2. 字符串结束字符 '\0' 也被视为字符串的一部分——strchr(s, '\0') 会返回指向结尾 '\0' 的指针，而不是 NULL
  3. 常用于查找分隔符：如用 strchr(line, ':') 找到冒号后截取字段

strrchr() — 查找最后一个指定字符

作用:: 在字符串中从后往前（从右向左）查找字符 c，返回最后一次出现（即从右往左第一次出现）的位置指针；找不到返回 NULL。

用法：

  • s：被查找的字符串
  • c：要查找的字符（int 类型）

注意事项：

  1. 查找方向与 strchr() 相反，返回的是最后一次出现的位置
  2. '\0' 同样参与查找（strrchr(s, '\0') 返回指向字符串结尾的指针）
  3. 典型应用：从文件路径中提取文件名——找最后一个 /

strstr() — 查找子字符串

作用:: 在给定字符串 haystack 中查找第一次出现子字符串 needle 的位置，返回指向该位置的指针；找不到返回 NULL。查找过程不包含 '\0'。

用法：

  • haystack：被查找的字符串
  • needle：要查找的子字符串

注意事项：

  1. 返回的指针指向 haystack 内部，可以通过指针偏移取出匹配位置之后的剩余内容
  2. 如果 needle 是空字符串 ""，返回 haystack 本身
  3. 与 strchr() 的区别：strchr() 找单个字符，strstr() 找子字符串（多个字符组成的序列）

字符串与数字互转

字符串 → 整型

函数 作用 成功返回 失败/无法解析
atoi() / atol() / atoll() 字符串转 int / long / long long（仅十进制，简单版） 转换结果 返回 0（无法区分）
strtol() / strtoll() / strtoul() / strtoull() 字符串转 long 系列（支持多进制、错误检测，✅ 推荐） 转换结果 溢出返回 LONG_MAX/LONG_MIN 并设置 errno；无有效数字返回 0

atoi() / atol() / atoll() — 字符串转整型（简单版）

作用:: 将数字字符串分别转换为 int、long int、long long int 类型的数据。只能转换十进制表示的数字字符串（0~9），自动跳过前导空白字符。

用法：

  • nptr：数字字符串，如 "123"、"-45"

注意事项：

  1. 没有错误检测：字符串不是合法数字时返回 0，无法区分是「真的输入了 0」还是「解析失败」
  2. 溢出行为未定义，不适用于对可靠性要求高的场景
  3. 遇到第一个非数字字符就停止解析（"123abc" 转成 123）
  4. 生产代码建议用 strtol() 系列替代

strtol() 家族 — 字符串转整型（增强版，推荐）

作用:: 将字符串转换为 long int（strtol）、long long int（strtoll）、unsigned long int（strtoul）、unsigned long long int（strtoull）类型数据。与 atoi() 不同，支持多种进制（二进制、八进制、十六进制等）的字符串，并带有完整的错误检测。

用法：

  • nptr：数字字符串
  • endptr：输出参数。不为 NULL 时，保存「停止解析的位置」指针，用于检测字符串是否被完整解析、以及取出剩余部分
  • base：进制，取值：
    • 0：自动识别——0x/0X 前缀按十六进制，0 前缀按八进制，否则按十进制
    • 2~36：指定进制（如 2 二进制、8 八进制、16 十六进制）

注意事项：

  1. 判断有没有解析出数字：*endptr == nptr（endptr 指向的位置与开头相同）→ 没有解析出任何数字
  2. 判断是否完整消费：*endptr == '\0' → 整个字符串都是合法数字
  3. 判断是否溢出：返回值等于 LONG_MAX/LONG_MIN 且 errno == ERANGE
  4. 支持前导空白、正负号、进制前缀（0x 等）自动处理
  5. 推荐用法：先 errno = 0; 清零，转换后同时检查 errno、endptr 和返回值

字符串 → 浮点型

函数 作用 成功返回 失败/无法解析
atof() 字符串转 double（简单版） 转换结果 返回 0.0（无法区分）
strtod() / strtof() / strtold() 字符串转 double / float / long double（增强版，✅ 推荐） 转换结果 溢出返回 ±HUGE_VAL 并设置 errno；无有效数字返回 0

atof() — 字符串转 double（简单版）

作用:: 将数字字符串转换为一个 double 类型的浮点数据，支持小数点和指数表示（如 3.14、1.5e-3）。

用法：

  • nptr：数字字符串，如 "3.14"、"2.5e3"

注意事项：

  1. 与 atoi() 一样没有错误检测：无法解析时返回 0.0，无法区分「输入就是 0.0」还是「解析失败」
  2. 生产代码建议用 strtod() 替代

strtod() 家族 — 字符串转浮点（增强版，推荐）

作用:: 将字符串转换为 double（strtod）、float（strtof）、long double（strtold）类型数据，带有完整的错误检测，支持小数、指数、inf/nan 等。

用法：

  • nptr：数字字符串
  • endptr：输出参数，保存停止解析的位置，用法同 strtol()

注意事项：

  1. 错误检测方法与 strtol() 相同：errno == ERANGE 判断溢出、endptr == nptr 判断无有效数字、*endptr != '\0' 判断未完整解析
  2. 支持十六进制浮点数（如 0x1.8p3）、inf/infinity/nan 等特殊值

数字 → 字符串

标准 C 语言没有 itoa() 函数（它不是 C 标准，glibc 也没有），数字转字符串的标准做法是用格式化函数 sprintf() / snprintf()（详细格式见《标准文件IO》笔记）：

  • str：目标缓冲区
  • size：缓冲区大小（含 '\0' 位置）
  • format：格式控制字符串

注意事项：

  1. 永远用 snprintf() 而不要用 sprintf()——后者不限制写入长度，缓冲区溢出风险高
  2. 返回值是「应写入的字符数」，如果 >= size，说明输出被截断了

正则表达式（POSIX 正则）

C 语言本身没有正则语法，Linux 下使用 POSIX 标准正则库 <regex.h>，核心是 regcomp()、regexec()、regerror()、regfree() 四个函数。

函数 作用 成功返回 失败返回
regcomp() 编译正则表达式 0 非 0 错误码
regexec() 用编译好的正则匹配字符串 0 REG_NOMATCH 等
regerror() 把错误码转成可读的错误信息 所需缓冲区大小 N/A
regfree() 释放编译时分配的资源 无返回值 N/A

基本概念：BRE 与 ERE

POSIX 正则分为两种模式，通过 regcomp() 的 cflags 选择：

  • 基本正则（BRE）：默认模式。+、?、|、()、{} 需要反斜杠转义才能生效（如 \+、\|）
  • 扩展正则（ERE）：指定 REG_EXTENDED 标志。+、?、|、()、{} 直接使用，书写更直观，推荐使用

常用元字符速查：

元字符 含义 示例
. 匹配任意单个字符 a.c 匹配 "abc"、"a1c"
* 前一个字符重复 0 次或多次 ab*c 匹配 "ac"、"abc"、"abbc"
+ 前一个字符重复 1 次或多次（ERE） ab+c 匹配 "abc" 但不匹配 "ac"
? 前一个字符出现 0 次或 1 次（ERE） colou?r 匹配 "color"、"colour"
^ 匹配行首 ^abc
$ 匹配行尾 abc$
[abc] 字符集，匹配其中任意一个 [0-9] 匹配数字
[^abc] 否定字符集 [^0-9] 匹配非数字
(ab) 分组（ERE） (ab)+ 匹配 "abab"
a|b 或（ERE） cat|dog
{m,n} 重复 m 到 n 次（ERE） [0-9]{3} 匹配 3 位数字
[[:digit:]] POSIX 字符类 [[:alpha:]] 字母、[[:space:]] 空白

regcomp() — 编译正则表达式

作用:: 把正则表达式字符串编译成内部格式（regex_t 结构），供 regexec() 使用。

用法：

  • preg：输出参数，保存编译结果
  • regex：正则表达式字符串
  • cflags：编译标志，常用：
    • REG_EXTENDED：使用扩展正则（ERE），推荐
    • REG_ICASE：匹配时忽略大小写
    • REG_NOSUB：不需要记录匹配位置（regexec() 可传 0 个匹配项），性能更好
    • REG_NEWLINE：把 ^/$ 按行处理

注意事项：

  1. 编译一次、匹配多次：regcomp() 开销较大，循环匹配时放在循环外面
  2. 编译失败时 preg 内容无效，不要调用 regfree()
  3. 编译成功后，用完必须调用 regfree() 释放资源

regexec() — 执行正则匹配

作用:: 用编译好的正则表达式在字符串中执行匹配，查找符合模式的内容。

用法：

  • preg：regcomp() 编译好的正则
  • string：待匹配的字符串
  • nmatch：pmatch 数组的元素个数
  • pmatch：输出参数，保存每个分组（含整个模式）的匹配位置：

pmatch[0] 是整个模式，pmatch[1] 起是第 1、2... 个括号分组

  • eflags：匹配标志，常用 REG_NOTBOL（string 中间位置，不是行首）、REG_NOTEOL

注意事项：

  1. pmatch[i].rm_so == -1 表示该分组没有参与匹配
  2. 匹配到的是第一个满足条件的位置；要找出所有匹配，需要循环调用并移动起始指针（见完整示例）
  3. 如果 regcomp() 指定了 REG_NOSUB，regexec() 应传 nmatch = 0、pmatch = NULL

regerror() — 获取错误信息

作用:: 将 regcomp() / regexec() 返回的错误码转换为可读的错误信息字符串。

用法：

  • errcode：错误码（如 regcomp() 的返回值）
  • preg：出错的正则（可为 NULL）
  • errbuf：输出缓冲区
  • errbuf_size：缓冲区大小

注意事项：

  1. 如果 errbuf_size 不够，错误信息会被截断；返回值大于 errbuf_size 说明被截断了
  2. 建议用足够大的定长数组，或先根据返回值分配缓冲区

regfree() — 释放正则资源

作用:: 释放 regcomp() 编译时分配的内存资源。只释放 regex_t 内部资源，不释放 regex_t 结构体本身（它通常在栈上）。

用法：

  • preg：regcomp() 编译成功的正则

注意事项：

  1. 只对编译成功的正则调用；编译失败不要调用
  2. 不释放 preg 指向的结构体本身（栈上变量无需释放，堆上分配的需要调用者自己 free()）
