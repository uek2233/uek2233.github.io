高级 I/O

📌 本笔记整理 Linux 应用编程中的"高级 I/O"相关内容，覆盖：阻塞/非阻塞 I/O、I/O 多路复用、信号驱动与异步 I/O、存储映射 I/O（mmap）、普通 I/O 与 mmap 的对比、文件锁。所有示例代码可在 GitHub 仓库 NAS-Ubuntu-Gcc-Linux 的 Advanced-IO/src/ 目录下找到（详见下方索引表）。

总览与学习路线

Linux 高级 I/O 主要解决两类问题：

  • 数据搬运效率：如何在用户态和内核态之间高效地传递数据（多路复用、mmap）。
  • 并发访问安全：多个进程/线程同时操作同一文件时如何避免竞争（文件锁）。

五种 I/O 模型

模型 典型接口 阻塞点 特点
阻塞 I/O read / write 数据未就绪时一直阻塞 简单，但无法并发
非阻塞 I/O fcntl(O_NONBLOCK) 不阻塞，立即返回 需轮询，CPU 占用高
I/O 多路复用 select / poll / epoll 阻塞在 select 等调用上 一个线程监视多个 fd
信号驱动 I/O fcntl(O_ASYNC) + SIGIO 不阻塞，数据就绪时收信号 实时信号可携带更多信息
异步 I/O (AIO) io_submit / POSIX AIO 完全不阻塞 真正的异步，Linux 实现有限

💡 学习顺序建议：先理解「阻塞 / 非阻塞」这一对基础概念 → 再学「如何同时监视多个 fd」（多路复用）→ 然后才知道为什么要「信号驱动 / 异步」→ 最后落到工程中最常用的「内存映射」和「文件锁」。

阻塞 I/O 与非阻塞 I/O

本章函数一览

函数 作用 头文件
fcntl() 获取 / 设置文件状态标志（用 O_NONBLOCK 设为非阻塞） <fcntl.h>

核心概念

  • 普通文件的读写操作不会阻塞，它总是以非阻塞的方式进行 I/O 操作。
  • 阻塞式 I/O 的优点在于能够提升 CPU 的处理效率：当自身条件不满足时进入阻塞状态，交出 CPU 资源给别人使用。
  • 非阻塞式 I/O 则是抓紧利用 CPU 资源，例如不断地轮询（busy-wait），这样会导致程序占用非常高的 CPU 使用率。
  • 阻塞式 I/O 的一个困境：无法实现并发读取（同时读取多个设备 / 文件）。
    • 例：一个进程同时读键盘和串口，若在键盘上阻塞，就无法处理串口数据。这正是后面「I/O 多路复用」要解决的问题。

⚠️ 非阻塞模式下，read 在无数据可读时不会阻塞，而是立即返回 -1 并置 errno = EAGAIN（或 EWOULDBLOCK，二者在 Linux 上等价）。因此非阻塞读写必须判断 errno。

fcntl() — 设置文件状态标志（O_NONBLOCK）

作用:: fcntl 是文件描述符的"万能工具箱"，F_GETFL / F_SETFL 用于读取和修改文件状态标志（如 O_NONBLOCK、O_ASYNC、O_APPEND）。由于 O_NONBLOCK 无法在程序内对继承来的 fd 重新 open，只能靠它追加。

用法：

  • fd：文件描述符。
  • cmd：操作命令，此处用 F_GETFL（获取）与 F_SETFL（设置）。
  • arg：F_SETFL 时传入新的标志值。

注意事项：

  • F_SETFL 只能追加少数几个标志（O_APPEND、O_ASYNC、O_NONBLOCK 等），访问模式（O_RDONLY/O_WRONLY/O_RDWR）不能改。
  • 标准输入 / 串口等设备 fd 只能通过 fcntl 设置非阻塞。
  • errno 为 EAGAIN/EWOULDBLOCK 表示"当前无数据"，不代表真正出错。

阻塞与非阻塞对比

对比项 阻塞 I/O 非阻塞 I/O
数据未就绪时 进程睡眠，让出 CPU 立即返回 -1 (EAGAIN)
CPU 占用 低 高（轮询 busy-wait）
实现难度 简单 需要自己写循环轮询
并发能力 单个 fd 阻塞即卡死 可轮询多个 fd

I/O 多路复用

本章函数一览

函数 作用 头文件

核心概念

I/O 多路复用可以监视多个文件描述符，一旦某个文件描述符（也就是某个文件）可以执行 I/O 操作时，能够通知应用程序进行相应的读写操作。

它与「非阻塞 + 轮询」的本质区别：非阻塞轮询是应用程序不断问内核"好了没"；多路复用是内核在内核态帮你同时等一批 fd，有事件了才唤醒你，因此既不用忙等，又能同时监视多个 fd。

select() — 监视多个文件描述符

作用:: 监视文件描述符 1. 是否可以接收数据？ 2. 是否可以无阻塞发送数据？ 3. 是否发生异常？，如果没有发生这些事件，则进入阻塞状态，超时后返回 0。

步骤：

  1. 设置文件描述符（fd_set）—— 将文件描述符设置为 1 即表示监听该文件描述符：

  2. 使用 select 函数设置监视范围及超时时间：

    • maxfd：监视对象文件描述符数量，由于文件描述符从 3 开始递增，因此该值为最大的文件描述符 + 1。
    • readset：将所有关注是否存在待读数据的文件描述符注册到 fd_set 型变量，并传递其地址值。
    • writeset：将所有关注是否可传输无阻塞数据的文件描述符注册到 fd_set 型变量，并传递其地址值。
    • exceptset：将所有关注是否发生异常的文件描述符注册到 fd_set 型变量，并传递其地址值。
    • timeout：为防止陷入无限阻塞状态，传递超时信息。

  3. 查看结果：调用 select 之后，fd_set 中的值将发生变化，原来为 1 的值是需要监视的文件描述符，这些文件描述符如果没有发生监视的事件则会变为 0，发生监视的事件则保持 1。

注意事项：

  1. 每次调用 select 之前都需重新初始化 timeval 结构体的成员变量，因为调用 select 之后 timeval 的成员变量被修改为超时前的剩余时间。
  2. 每次调用 select 之前都需要拷贝 fd_set，保留初始值，这是因为调用 select 之后 fd_set 中没有发生事件的文件描述符都被初始化为 0。
  3. 阻塞态可能会被信号打断：正在阻塞等待期间收到一个会被捕获（caught）的信号，它通常会被信号打断并提前返回，此时 select() 返回 -1，并设置 errno = EINTR。
  4. select 可监视的 fd 数量受 FD_SETSIZE 限制（通常为 1024）。

poll() — 监视多个文件描述符（无数量上限）

作用:: 是一种经典的 I/O 多路复用机制，用于同时监视多个文件描述符（File Descriptor, fd）上的事件。它的主要作用是允许程序在单个线程内等待多个网络套接字或设备文件的状态变化，当某个文件描述符就绪（如可读、可写或出错）时，内核会通知程序进行相应的处理。

用法：

参数 / 返回值 说明
fds 指向一个 struct pollfd 结构体数组的指针，用于指定要监视的文件描述符及其关注的事件。
nfds fds 数组中的元素个数，类型为 nfds_t（通常为无符号整型）。
timeout 超时时间（单位为毫秒，ms）。若为 0 则立即返回；若为 -1 则永久阻塞，直到有事件发生。

事件掩码：

掩码 含义 触发条件 & 适用场景 备注
POLLIN 有数据可读取 文件描述符对应的对象中有数据可读，例如 socket 接收到数据、管道中有数据等 最常用的可读事件
POLLNORM 有普通数据可读取 普通数据已经准备好，可以进行读取 通常与 POLLIN 等价
POLLRDBAND 有优先级数据可读取 有带优先级的数据可读取 Linux 上通常不使用
POLLPRI 有高优先级数据可读取 有紧急（urgent）或高优先级数据到达 比普通数据优先级更高
POLLRDHUP 对端关闭写端 TCP socket 对端执行半关闭（shutdown(SHUT_WR)）或对端连接关闭时触发 Linux 扩展，常用于检测 TCP 对端关闭
POLLOUT 可以写入数据 文件描述符对应的对象当前可以写入数据，不会立即阻塞 最常用的可写事件
POLLWRNORM 可以写入普通数据 文件描述符可以进行普通数据写入 通常与 POLLOUT 等价
POLLWRBAND 可以写入优先级数据 可以写入带优先级的数据 优先级数据相关，实际较少使用
POLLERR 发生错误 文件描述符对应的对象发生错误，例如 socket 出现错误 只作为返回事件使用，不能作为 events 请求
POLLHUP 发生挂断 对端关闭连接、管道写端关闭等导致挂断 只作为返回事件使用，不能作为 events 请求
POLLNVAL 文件描述符无效 fd 没有打开，或者传入了无效的文件描述符 只作为返回事件使用，不能作为 events 请求
POLLMSG 消息事件 表示有消息到达 Linux 中不使用

poll 的优势与劣势：

  • 与 select 相比：
    • poll 没有文件描述符数量的硬性上限（而 select 受限于 1024 个描述符）。
    • poll 的 events 和 revents 相互独立，在每次调用后不会重置事件掩码，因此无需像 select 那样每次调用前重新初始化描述符集合。
  • 局限性：
    • 与 select 类似，每次调用 poll 时都需要在用户态和内核态之间整体复制 pollfd 数组，当监听的文件描述符非常庞大时，性能开销会急剧增大。
    • 在处理海量长连接时，现代 Linux 系统通常会使用性能更优秀的 epoll。

epoll() — 补充：Linux 下最高效的多路复用

select / poll 每次调用都要把整个 fd 集合从用户态拷贝到内核态，并在内核里线性扫描。epoll 通过在内核维护一棵"红黑树 + 就绪链表"解决了这个问题，是处理海量并发连接（如高并发服务器）的标准做法。

触发模式：

信号驱动 I/O 与异步 I/O

本章函数一览

函数 作用 头文件
fcntl() 用 O_ASYNC 使能异步 I/O；F_SETOWN 设置接收进程；F_SETSIG 指定通知信号 <fcntl.h>
signal() 为信号注册处理函数（简单版） <signal.h>
sigaction() 为信号注册处理函数（可携带信息版，配合 SA_SIGINFO） <signal.h>
pause() 让进程挂起，直到收到一个信号 <unistd.h>

核心概念

进程通过系统调用 select() 或 poll() 来主动查询文件描述符上是否可以执行 I/O 操作。而在异步 I/O 中，当文件描述符上可以执行 I/O 操作时，进程可以请求内核为自己发送一个信号。之后进程就可以执行任何其它的任务，直到文件描述符可以执行 I/O 操作时为止，此时内核会发送信号给进程。

信号驱动 I/O 的步骤

  1. 通过指定 O_NONBLOCK 标志使能非阻塞 I/O（避免在信号处理里读数据时又阻塞）。
  2. 通过指定 O_ASYNC 标志使能异步 I/O。
  3. 设置异步 I/O 事件的接收进程。也就是当文件描述符上可执行 I/O 操作时会发送信号通知该进程，通常将调用进程设置为异步 I/O 事件的接收进程。
  4. 为内核发送的通知信号注册一个信号处理函数。默认情况下，异步 I/O 的通知信号是 SIGIO，所以内核会给进程发送信号 SIGIO。
  5. 以上步骤完成之后，进程就可以执行其它任务了，当 I/O 操作就绪时，内核会向进程发送一个 SIGIO 信号，当进程接收到信号时，会执行预先注册好的信号处理函数，我们就可以在信号处理函数中进行 I/O 操作。

注册 SIGIO 信号处理函数

通过 signal() 或 sigaction() 函数为 SIGIO 信号注册一个信号处理函数，当进程接收到内核发送过来的 SIGIO 信号时，会执行该处理函数。

优化异步 I/O

默认的异步 I/O 通知信号 SIGIO 存在两个问题：

  • SIGIO 是非排队信号，它不支持信号排队机制，只有当信号处理函数执行完毕之后才会传递给进程，并且只能传递一次，而其它后续的信号都会丢失。
  • 无法得知文件描述符发生了什么事件，是可读取还是可写入亦或者发生异常等。

解决办法：使用 fcntl() 函数指定一个实时信号作为异步 I/O 通知信号。如果第三个参数 arg 设置为 0，则表示指定 SIGIO 信号作为异步 I/O 通知信号，也就是回到默认状态：

在应用程序当中需要为实时信号注册信号处理函数，使用 sigaction 函数进行注册，并为 sa_flags 参数指定 SA_SIGINFO，表示使用 sa_sigaction 指向的函数作为信号处理函数，而不使用 sa_handler 指向的函数。对于异步 I/O 事件而言，传递给信号处理函数的 siginfo_t 结构体中与之相关的字段如下：

  • si_signo：信号编号（例如 SIGIO 或自定义的实时信号）。
  • si_code：信号产生的原因 / 代码（例如 SI_ASYNCIO 表示由异步 I/O 发起，POLL_IN 表示可读）。
  • si_value (sigval_t)：携带的用户自定义数据或联合体（通过 aio_sigevent 传递的 sigval 值，通常包含指向 struct aiocb 的指针）。
  • si_fd：触发信号的文件描述符（在某些信号驱动 I/O 场景下使用）。

⚠️ 实时信号是排队的，因此不会像 SIGIO 那样丢失；并且通过 siginfo_t 能拿到具体事件类型，弥补了默认方案的两个缺陷。这正是 async2.cc 相对 async1.cc 的改进点。

核心概念

存储映射 I/O（Memory-Mapped I/O，简称 mmap）是 Linux 系统中一种高效的高级 I/O 机制，它能将磁盘文件或设备空间直接映射到进程的虚拟地址空间中。

主要系统调用：

  • mmap()：创建内存映射，将文件描述符或特定地址关联到进程虚拟内存。
  • munmap()：解除内存映射。
  • msync()：将内存区域中的修改同步回磁盘文件。

主要应用场景：

  • 大文件高效读写：比普通文件读写速度更快，适合随机访问大文件。
  • 进程间通信（IPC）：多个进程可以映射同一个文件或匿名内存实现高效的共享内存通信。
  • 动态库加载：Linux 系统加载共享库（.so 文件）时普遍使用内存映射技术。

mmap() — 创建内存映射

参数：

  • addr：指定映射的起始地址，通常设为 NULL，由内核自行选择。
  • length：映射的数据长度（以字节为单位）。
  • prot：映射区域的保护权限（如 PROT_READ 读、PROT_WRITE 写、PROT_EXEC 执行、PROT_NONE 禁止访问）。
  • flags：映射类型的标志（如 MAP_SHARED 共享修改、MAP_PRIVATE 私有复制写、MAP_ANONYMOUS 匿名映射）。
  • fd：有效的文件描述符（通过 open() 获得）；匿名映射时传 -1。
  • offset：文件映射的起始偏移量，通常为 0。

注意事项：

  • addr 和 offset 的值通常被要求是系统页大小的整数倍，可通过 sysconf(_SC_PAGESIZE) 函数获取页大小。
  • 操作系统采用页式管理，调用 mmap() 后并不会立刻把整个文件读入物理内存，而是在访问特定内存页时触发缺页中断再加载。
  • MAP_SHARED 的修改会反映到文件（其它映射该文件的进程也能看到）；MAP_PRIVATE 的修改则是写时复制（copy-on-write），不会影响文件本身。
  • 如果映射一个文件却想写入，fd 必须以 O_RDWR 打开，且 prot 要包含 PROT_WRITE。

与映射区相关的两个信号：

  • SIGSEGV：如果映射区被 mmap() 指定成了只读的，那么进程试图将数据写入到该映射区时，将会产生 SIGSEGV 信号。
  • SIGBUS：如果映射区的某个部分在访问时已不存在（如文件被截断），则会产生 SIGBUS 信号。

munmap() — 解除内存映射

参数：

  • addr：要取消映射的内存区域的起始地址，必须是页大小（page size）的整数倍（通常由 mmap 返回）。
  • length：要取消映射的内存大小（以字节为单位），通常也是页大小的整数倍。

注意事项：

  • 当进程终止时也会自动解除映射。
  • munmap() 函数并不影响被映射的文件，也就是说，当调用 munmap() 解除映射时并不会将映射区中的内容写到磁盘文件中。
  • 如果 mmap() 指定了 MAP_SHARED 标志，对于文件的更新，会在我们将数据写入到映射区之后的某个时刻将映射区中的数据更新到磁盘文件中，由内核根据虚拟存储算法自动进行。

mprotect() — 修改映射区保护权限

系统调用 mprotect() 可以更改一个现有映射区的保护要求。

  • addr：起始地址，必须是页大小整数倍。
  • len：区域长度，通常为页大小整数倍。
  • prot：新的保护权限（PROT_READ / PROT_WRITE / PROT_EXEC / PROT_NONE）。

💡 典型用途：先用 PROT_READ|PROT_WRITE 构建好一块数据，再 mprotect 成 PROT_READ 变成"只读常量区"；或实现简单的内存越界检测。

msync() — 同步映射区到磁盘

写入到文件映射区中的数据也不会立马刷新至磁盘设备中，而是会在我们将数据写入到映射区之后的某个时刻将映射区中的数据写入磁盘中。所以会导致映射区中的内容与磁盘文件中的内容不同步。我们可以调用 msync() 函数将映射区中的数据刷写、更新至磁盘文件中。

参数 addr 和 length 指定了需同步的内存区域的起始地址和大小，同样也要求必须是系统页大小的整数倍。

  • MS_ASYNC：以异步方式进行同步操作。调用 msync() 函数之后，并不会等待数据完全写入磁盘之后才返回。
  • MS_SYNC：以同步方式进行同步操作。调用 msync() 函数之后，需等待数据全部写入磁盘之后才返回。
  • MS_INVALIDATE：是一个可选标志，请求使同一文件的其它映射无效（以便可以用刚写入的新值更新它们）。

ftruncate() — 改变已打开文件大小

作用:: 用来改变已打开文件大小的系统函数，如果原文件大小大于 length，超过的部分会被丢弃。在 mmap 之前对输出文件调用 ftruncate 是必须的：因为新创建的文件长度为 0，直接映射并写入会触发 SIGBUS。

用法：

  • fd：已打开文件的文件描述符。
  • length：设置的目标长度（以字节为单位）。

注意：

  • 文件权限：调用该函数前，文件必须以写入模式（如 O_WRONLY 或 O_RDWR）打开。
  • 文件偏移量：ftruncate 不会自动改变当前的读写偏移量。如果在清空或截断后继续写入，建议配合 lseek 重新设置偏移量。

普通 I/O 与存储映射 I/O 比较

普通 I/O 方式的缺点：

  • 数据需要在不同的缓存间倒腾，效率会比较低。

存储映射 I/O 的优点：

  • 源文件和目标文件都已映射到了应用层的内存区域中，所以直接操作映射区来实现。
  • 映射区就是应用层与内核层之间的共享内存。

存储映射 I/O 的不足：

  • 映射的文件只能是固定大小。
  • 文件映射的内存区域的大小必须是系统页大小的整数倍。

普通 I/O（常规系统调用）

普通 I/O 依赖于 read、write、lseek 等系统调用。每次调用都会触发内核态与用户态的切换。

👍 优点：

  • 简单稳定：API 逻辑简单，符合传统的流式处理逻辑，不容易出错。
  • 适合流式数据：非常适合处理管道（Pipe）、套接字（Socket）等无法在内存中定位长度的流式数据。
  • 内存受限时表现更好：不需要将文件内容映射到连续的虚拟地址空间，处理超大文件时不会大量消耗虚拟内存地址。

👎 缺点：

  • 多次内存拷贝开销：数据必须先从磁盘复制到内核的页缓存（Page Cache），再从页缓存复制到用户空间缓冲区。
  • 高频系统调用开销：如果需要频繁读写小块数据，频繁的内核态切换会带来巨大的 CPU 损耗。

存储映射 I/O（mmap）

👍 优点：

  • 零用户态拷贝（Zero-copy）：省去了内核缓冲区到用户缓冲区的内核复制步骤，数据直接通过页缓存与磁盘同步。
  • 减少系统调用：映射建立后，读写文件不再需要 read/write 系统调用，而是触发操作系统的缺页中断（Page Fault）自动加载。
  • 高效的随机访问：因为文件被当作内存数组处理，可以通过指针直接跳转到任意位置，极适合数据库等需要频繁随机读写的场景。
  • 进程间内存共享：多个进程可以映射同一个文件，实现高效的共享内存通信。

👎 缺点：

  • 映射和缺页开销：建立映射的初始化开销较大。如果文件很小，mmap 的性能可能不如普通 I/O。
  • 地址空间碎片化：大量使用 mmap 会消耗进程的虚拟地址空间，可能导致内存碎片。
  • 特殊错误处理复杂：如果映射的文件被其他进程截断（Truncate），访问相应内存会触发 SIGBUS 信号导致程序崩溃，处理起来较麻烦。
  • 空间对齐浪费：mmap 必须以内存页（通常是 4KB）为单位进行映射。如果文件只有几个字节，也会占用一整页内存，造成空间浪费。

维度 普通 I/O 存储映射 I/O (mmap)

核心概念

当多个进程同时操作同一文件时，Linux 通常采用的方法是对文件上锁，来避免多个进程同时操作同一文件时产生竞争状态。

文件锁的分类：

  • 建议性锁（Advisory Lock）：内核只提供加锁、解锁和检测锁的 API，但不主动检查进程在读写文件前是否加了锁，它建立在"君子协定"基础上。所有参与操作的进程必须自觉在读写前先去调用 API 检测锁，如果某个进程不守规矩，完全无视锁的存在直接去 open、read 或 write，内核不会阻拦，操作依然会成功。
  • 强制性锁（Mandatory Lock）：如果进程对文件上了强制性锁，其它的进程在没有获取到文件锁的情况下是无法对文件进行访问的。
  • 现代操作系统（如 Linux）默认不开启强制锁，因为强制锁会带来潜在的安全风险和性能开销。

flock() — 对整文件加建议性锁

函数可以对文件加锁或者解锁，但是 flock() 函数只能产生建议性锁。

  • fd：文件描述符，通过 open() 打开文件获得。
  • operation：操作类型参数
    • LOCK_SH（共享锁）：多个进程可以同时对同一个文件获取共享锁（读锁）。
    • LOCK_EX（排他锁 / 独占锁）：只有一个进程能获取排他锁（写锁），常用于写入文件。
    • LOCK_UN（解锁）：解除文件锁。
    • LOCK_NB（非阻塞）：通过和上面三个操作按位或（如 LOCK_EX | LOCK_NB）使用。如果无法立即获得锁，函数会立即返回 -1 并不阻塞等待。

注意事项：

  • 同一个文件不会同时具有共享锁和互斥锁。
  • 同一进程对文件多次加锁不会导致死锁。当进程调用 flock() 对文件加锁成功，再次调用 flock() 对文件（同一文件描述符）加锁，这样不会导致死锁，新加的锁会替换旧的锁。
  • 文件关闭的时候，会自动解锁。
  • 一个进程不可以对另一个进程持有的文件锁进行解锁。
  • 由 fork() 创建的子进程不会继承父进程所创建的锁。
  • 当一个文件描述符被复制时（譬如使用 dup()、dup2() 或 fcntl() 的 F_DUPFD 操作），这些通过复制得到的文件描述符和源文件描述符都会引用同一个文件锁，使用这些文件描述符中的任何一个进行解锁都可以。

fcntl() — 记录锁 / 文件锁（可精确到字节）

五大核心功能与常见用法：

  1. 复制文件描述符（F_DUPFD）
  2. 获取 / 设置文件描述符标志（F_GETFD / F_SETFD）
  3. 获取 / 设置文件状态标志（F_GETFL / F_SETFL）
  4. 获取 / 设置异步 I/O 所有权（F_GETOWN / F_SETOWN）
  5. 获取 / 设置记录锁 / 文件锁（F_GETLK / F_SETLK / F_SETLKW）
    • F_GETLK：测试是否可以加锁（不真正加锁，若已被占用则在结构体中返回占用者信息）。
    • F_SETLK：非阻塞地加锁或解锁（若冲突则立即返回 -1 且 errno 为 EACCES 或 EAGAIN）。
    • F_SETLKW：阻塞等待式加锁（若冲突则进程进入睡眠，直到锁可用或被信号中断）。

flock() 与 fcntl() 加锁的区别：

  • flock() 仅支持对整个文件进行加锁 / 解锁；而 fcntl() 可以对文件的某个区域（某部分内容）进行加锁 / 解锁，可以精确到某一个字节数据。
  • flock() 仅支持建议性锁类型；而 fcntl() 可支持建议性锁和强制性锁两种类型。

  • 若参数 l_len 设置为 0，表示将锁区域扩大到最大范围，也就是说从锁区域的起始位置开始，到文件的最大偏移量处（也就是文件末尾）都处于锁区域范围内。而且是动态的，这意味着不管向该文件追加写了多少数据，它们都处于锁区域范围，起始位置可以是文件的任意位置。

  • 一个进程不可以对另一个进程持有的文件锁进行解锁。
  • 由 fork() 创建的子进程不会继承父进程所创建的锁。
  • 通过复制得到的文件描述符和源文件描述符都会引用同一个文件锁，使用这些文件描述符中的任何一个进行解锁都可以。

补充：定位读写 pread() / pwrite()

这类"在指定偏移处读写、且不改动文件当前偏移量"的接口，在多线程 / 多进程同时访问同一文件时非常有用，可以避免 lseek + read 的竞争。与 mmap 属于同一类"高级文件访问"手段。

作用:: pread 是 Unix/Linux 系统中的一个系统调用函数，用于从文件的指定偏移量处读取数据，且不改变文件的当前读写指针位置。

用法：

  • fd：文件描述符。
  • buf：存放读取数据的缓冲区（pwrite 为待写入数据）。
  • count：要读取 / 写入的字节数。
  • offset：指定的开始读取 / 写入位置（文件偏移量）。

注意：

  • 不改变文件指针：调用 pread 后，文件当前的共享偏移指针（由 lseek 或常规读写维护的指针）保持不变。
  • 原子操作：pread 将"定位（lseek）"和"读取（read）"合并为一个不可中断的原子操作。
  • 多线程安全：在多线程环境中，如果多个线程共享同一个文件描述符，分别用 lseek 加 read 会互相干扰文件指针。而使用 pread 可以避免竞争条件。

与 read 函数的区别：

特性 read pread
读位置 从文件的当前偏移量开始读 从指定的 offset 位置开始读
更新指针 会更新文件描述符的当前偏移量 不会改变文件的当前偏移量
原子性 单独调用无法保证与 lseek 的原子性 定位与读取是一个原子操作

小结

主题 核心接口 一句话记住
非阻塞 I/O fcntl(O_NONBLOCK) 无数据立即返回 EAGAIN，不睡但费 CPU
I/O 多路复用 select / poll / epoll 一个线程同时等多个 fd，有事件才醒
信号驱动 / 异步 I/O fcntl(O_ASYNC) + SIGIO/实时信号 内核数据就绪时发信号给你
存储映射 I/O mmap / munmap / msync / ftruncate 文件当内存数组用，够快但要求页对齐
文件锁 flock / fcntl 记录锁 多进程写同一文件要上锁，flock 整文件、fcntl 到字节
