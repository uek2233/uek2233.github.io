Linux 应用编程：标准文件 IO

标准文件 IO

标准 I/O 库是标准 C 库中用于文件 I/O 操作的接口，标准 I/O 和文件 I/O 的区别如下：

对比项 标准 I/O（stdio） 文件 I/O（系统调用）
本质 标准 C 库函数 Linux 系统调用
来源 由文件 I/O 封装而来 内核直接提供
可移植性 不同操作系统之间可移植性好 依赖操作系统
缓冲 用户空间维护 stdio 缓冲区，带缓存 用户空间无缓存
性能/效率 更优（减少系统调用次数） 每次读写都陷入内核

💡 标准 I/O 底层依然是文件 I/O：fopen() 内部会调用 open()，fread()/fwrite() 内部会调用 read()/write()，只是额外加了一层用户空间的 stdio 缓冲。

FILE 指针

对于标准 I/O 库函数的操作是围绕 FILE 指针进行的。

  • FILE 是一个结构体类型，定义在标准 I/O 库头文件 stdio.h 中，用于描述一个打开的文件流（stream）
  • FILE 结构体内部维护了：文件描述符、stdio 缓冲区（缓冲模式、缓冲指针、读写位置）、错误指示符、EOF 指示符等信息
  • 标准 I/O 库函数都以 FILE * 作为操作句柄，类似于文件 I/O 中的 fd
  • 由于 FILE 内部的成员是实现相关的，不要直接访问其成员，只能通过标准 I/O 库函数间接操作

标准输入、标准输出和标准错误

每个进程启动之后都会默认打开标准输入、标准输出以及标准错误，对应三个文件描述符 0、1、2：

名称 文件描述符 FILE 指针 默认设备
标准输入 stdin 0 stdin 键盘
标准输出 stdout 1 stdout 终端
标准错误 stderr 2 stderr 终端

📌 文件 I/O 中用 STDIN_FILENO 等宏（定义于 <unistd.h>）操作这 3 个 fd；标准 I/O 中则直接使用 stdin、stdout、stderr 这 3 个 FILE 指针，无需 open。stderr 默认无缓冲，stdout 在终端下默认行缓冲。

I/O 操作函数

函数 作用 成功返回 失败返回

fclose() 关闭文件（自动刷新缓冲） 0 EOF(-1)
fread() 从文件读取数据 读取的元素个数 0 或 <nmemb
fwrite() 向文件写入数据 写入的元素个数 <nmemb
fgetc() 读一个字符 字符的 ASCII 码 EOF
fputc() 写一个字符 写入的字符 EOF

fopen() — 打开文件

作用:: 打开或创建指定的文件，并返回指向 FILE 类型对象的指针

用法：

  • path：要打开的文件路径（绝对路径或相对路径）
  • mode：文件打开模式（见下表）

mode 常用值：

mode 含义
"r" 只读打开，文件必须存在
"w" 只写打开，文件不存在则创建，存在则截断为 0
"a" 追加写，文件不存在则创建，每次写都从末尾开始
"r+" 读写打开，文件必须存在
"w+" 读写打开，不存在则创建，存在则截断
"a+" 读 + 追加写，不存在则创建
"rb" / "wb" 等 二进制模式（Linux 下与文本模式无区别，Windows 下有区别）

注意事项：

  1. fopen() 是库函数，内部会调用 open() 系统调用，并额外创建 stdio 缓冲区
  2. 打开成功必须调用 fclose() 关闭，否则会泄漏文件描述符和缓冲区内存
  3. 与 open() 的对应关系："r"≈O_RDONLY，"w"≈O_WRONLY|O_CREAT|O_TRUNC，"a"≈O_WRONLY|O_CREAT|O_APPEND
  4. 判断失败时用 perror() 或 strerror(errno) 打印具体原因

fclose() — 关闭文件

作用:: 关闭指定的文件流，释放 FILE 指针占用的资源

用法：

  • stream：fopen() 返回的 FILE 指针

注意事项：

  1. 调用 fclose() 时会自动刷新 stdio 缓冲区，把缓冲中未写出的数据写入文件
  2. 关闭之后 FILE 指针不能再使用（成为野指针），建议置 NULL
  3. 程序正常退出时会自动关闭所有打开的文件流，但显式 fclose 是好习惯
  4. 重复 fclose 同一个流是未定义行为，不要这样做

fread() — 读数据

作用:: 从文件流中读取数据到缓冲区

用法：

  • ptr：存放读取数据的缓冲区
  • size：每个数据元素的大小（字节数）
  • nmemb：要读取的元素个数
  • stream：FILE 指针

注意事项：

  1. 返回值是元素个数而不是字节数！实际读取的字节数 = 返回值 × size
  2. 返回值 < nmemb 时，可能是到达文件末尾，也可能是出错，用 feof() / ferror() 区分
  3. 读取二进制数据（结构体、数组）时特别方便，一次可以读写多个元素
  4. 常用的整文件读取技巧：先 fseek 到末尾 ftell 拿大小，再 rewind 回来一次性读完

fwrite() — 写数据

作用:: 将缓冲区中的数据写入到文件流

用法：

  • ptr：要写入的数据缓冲区
  • size：每个数据元素的大小（字节数）
  • nmemb：要写入的元素个数
  • stream：FILE 指针

注意事项：

  1. 返回值 < nmemb 表示写入出错（如磁盘空间不足），需要检查 errno
  2. fwrite 写入的是用户缓冲区中的数据，数据真正落盘还依赖刷新内核缓冲（fsync 等），见下文「I/O 缓冲」
  3. 与 fread 配合可实现结构体等二进制数据的持久化

fgetc() & fputc() — 字符读写

作用:: fgetc() 从文件流读取一个字符；fputc() 向文件流写入一个字符

用法：

  • c：要写入的字符（int 类型，实际取低 8 位）
  • stream：FILE 指针

注意事项：

  1. 接收 fgetc 的返回值必须用 int 类型，不能用 char——因为 EOF(-1) 无法用 char 表示，用 char 会导致无法区分「字符 0xFF」和「文件末尾」
  2. fgetc 读到文件末尾返回 EOF，可用 feof() 确认
  3. fputc 返回的也是 int，判断是否等于 EOF 即可知道是否写失败

fgets() & fputs() — 行读写

作用:: fgets() 从文件流读取一行字符串；fputs() 向文件流写入一行字符串

用法：

  • s：存放/输出字符串的缓冲区
  • size：缓冲区大小，最多读取 size-1 个字符，末尾自动补 '\0'
  • stream：FILE 指针

注意事项：

  1. fgets 读到换行符就停止，会把 '' 也存入缓冲区（如果缓冲区装得下），并在末尾补 '\0'
  2. 缓冲区大小要足够，否则一行会被拆成多次读取
  3. fputs 只输出字符串内容，不会自动添加换行符，需要换行时自己加 "\n"
  4. 常用组合：fgets(buf, sizeof(buf), fp) 循环读取，直到返回 NULL（读完全部行）

fseek() — 移动读写位置

作用:: 设置文件流的读写位置偏移量（相当于文件 I/O 中的 lseek()）

用法：

  • stream：FILE 指针
  • offset：偏移量，可正可负
  • whence：基准位置

whence 常用值：

宏 含义
SEEK_SET 从文件开头算起（offset >= 0）
SEEK_CUR 从当前位置算起
SEEK_END 从文件末尾算起（offset 可为负，表示向前）

注意事项：

  1. fseek 只移动读写位置，不读写数据
  2. 如果偏移量超过文件末尾，之后再写入会形成空洞文件（中间补 '\0'）
  3. fseek 会清除文件的 EOF 指示符，方便重新读取
  4. 以追加模式（"a"/"a+"）打开的文件，写入位置始终在末尾，fseek 定位无效

ftell() & rewind()

作用:: ftell() 获取文件当前读写位置偏移量；rewind() 将读写位置重置到文件开头

用法：

  • stream：FILE 指针

注意事项：

  1. rewind() 等价于 (void)fseek(stream, 0L, SEEK_SET)，同时清除错误指示符和 EOF 指示符
  2. 常用技巧：fseek(fp, 0, SEEK_END) + ftell(fp) 获取文件大小
  3. 对于以文本模式打开的文件，ftell 的返回值可能不是精确的字节数（Linux 下无此问题）

feof() — 检测文件末尾

作用:: 检测文件流是否已经到达文件末尾

用法：

  • stream：FILE 指针

注意事项：

  1. EOF 指示符是在一次读取操作遇到文件末尾之后才被置位的——feof() 本身不读取数据，所以在读取之前调用它没有意义
  2. 典型用法：读取函数返回 0/EOF 后，用 feof() 判断是「正常读完」还是「出错」
  3. 清除 EOF 指示符需要使用 clearerr() 或 rewind()/fseek()

ferror() — 检测错误

作用:: 检测文件流是否发生了读写错误

用法：

  • stream：FILE 指针

注意事项：

  1. 错误指示符一旦被置位会一直保持，直到调用 clearerr() 或 rewind() 清除
  2. 与 feof() 一样，它本身不触发任何操作，只是查询状态
  3. 想了解具体错误原因，用 errno + perror()

clearerr() — 清除指示符

作用:: 清除文件流的 EOF 指示符和错误指示符

用法：

  • stream：FILE 指针

注意事项：

  1. 清除之后，feof() 和 ferror() 都会重新返回 0
  2. 常见场景：对同一个文件流做多轮读取，每轮之间需要 clearerr 重置状态
  3. rewind() 和 fseek() 也会顺带清除指示符

格式化 I/O

格式化输出

函数 输出目标 成功返回 失败返回
printf() 标准输出 stdout 输出的字符数 负数
fprintf() FILE 指针指定的文件 输出的字符数 负数
dprintf() 文件描述符 fd 指定的文件 输出的字符数 -1
sprintf() 用户缓冲区（可能溢出！） 应写入的字符数 负数
snprintf() 用户缓冲区（限 size） 应写入的字符数（不含 '\0'） 负数
  • printf() 函数用于将格式化数据写入到标准输出；
  • dprintf() 和 fprintf() 函数用于将格式化数据写入到指定的文件中，两者不同之处在于：fprintf() 使用 FILE 指针指定对应的文件，而 dprintf() 则使用文件描述符 fd 指定对应的文件；
  • sprintf()、snprintf() 函数可将格式化的数据存储在用户指定的缓冲区 buf 中。需要注意的是，sprintf() 函数可能会造成由参数 buf 指定的缓冲区溢出，为了解决这个问题，引入了 snprintf() 函数：在该函数中，使用参数 size 显式地指定缓冲区的大小，如果写入到缓冲区的字节数大于参数 size 指定的大小，超出的部分将会被丢弃，并且会在末尾自动添加终止字符 '\0'。

printf()

作用:: 将格式化数据写入到标准输出

用法：

  • format：格式控制字符串
  • ...：可变参数，与 format 中的格式符一一对应

注意事项：

  1. 输出到 stdout，stdout 在终端下默认行缓冲，遇到 '' 才会刷新
  2. 返回值是实际输出的字符数，一般用不到

fprintf()

作用:: 将格式化数据写入到 FILE 指针指定的文件中

用法：

  • stream：目标文件的 FILE 指针
  • format：格式控制字符串
  • ...：可变参数

注意事项：

  1. 与 printf 的唯一区别就是多了一个 stream 参数，可以输出到任意文件
  2. 常用于日志输出：fprintf(stderr, ...) 输出到标准错误，不经过行缓冲，立即显示
  3. 输出到文件时数据先进入 stdio 缓冲区，注意调用 fflush 或 fclose 才会真正写入

dprintf()

作用:: 将格式化数据写入到文件描述符 fd 指定的文件中

用法：

  • fd：目标文件的文件描述符（如 open() 的返回值、STDOUT_FILENO 等）
  • format：格式控制字符串
  • ...：可变参数

注意事项：

  1. 与 fprintf 的区别：dprintf 使用文件描述符 fd，fprintf 使用 FILE 指针——常用于配合 open()/socket() 直接输出
  2. 它是 POSIX 扩展函数，glibc 下需要定义 _GNU_SOURCE 或 _POSIX_C_SOURCE >= 200809L 才能使用
  3. dprintf 不经过 stdio 缓冲，直接写内核缓冲区

sprintf() & snprintf()

作用:: 将格式化数据写入到用户指定的缓冲区 buf 中

用法：

  • str：目标缓冲区
  • size：缓冲区大小（snprintf 才有）
  • format：格式控制字符串
  • ...：可变参数

注意事项：

  1. sprintf() 不检查缓冲区大小，极易造成缓冲区溢出（安全隐患，可能导致程序崩溃或被攻击），应尽量使用 snprintf()
  2. snprintf() 最多写入 size-1 个字符，并自动在末尾补 '\0'，超出的部分被丢弃
  3. 返回值是「本应写入的字符数」（不含 '\0'）：如果返回值 >= size，说明发生了截断
  4. 判断截断后可以重新分配更大的缓冲区再格式化

格式化输入

函数 输入来源 成功返回 失败返回

  • fscanf() 函数从 FILE 指针指定文件中读取数据，并将数据进行格式化转换；

scanf()

作用:: 从标准输入读取数据并进行格式化转换

用法：

  • format：格式控制字符串
  • ...：必须传入变量的地址（&x），不能直接传变量

注意事项：

  1. 参数必须取地址：scanf("%d", &num)，漏掉 & 会导致段错误
  2. 返回值表示成功匹配的个数，可以用来判断输入是否合法
  3. 用 %s 读取字符串时没有边界检查，输入过长会缓冲区溢出——建议用宽度限制 %19s 或改用 fgets()
  4. 输入流在遇到空白字符（空格、Tab、换行）时会跳过，%c 除外（%c 会读取包括空格在内的任何字符）

fscanf()

作用:: 从 FILE 指针指定的文件中读取数据并进行格式化转换

用法：

  • stream：源文件的 FILE 指针
  • format：格式控制字符串
  • ...：变量的地址

注意事项：

  1. 常用于解析格式化文本文件（如配置文件、CSV）
  2. 读取到文件末尾返回 EOF，可用 feof() 确认
  3. 与 fgets 搭配：先用 fgets 读一行，再用 sscanf 解析该行，更安全可控

sscanf()

作用:: 从字符串中读取数据并进行格式化转换

用法：

  • str：源字符串
  • format：格式控制字符串
  • ...：变量的地址

注意事项：

  1. sscanf 不会产生任何 I/O，是纯内存操作，常用于字符串解析
  2. 经典用法：从"2026-08-10"这样的字符串中提取年、月、日
  3. 解析失败时返回值小于期望个数，务必检查返回值

格式控制字符串 format（输入）

输入格式符与输出基本一致（%d、%x、%f、%s、%c 等），但有几点不同：

注意点 说明
参数传地址 必须传变量的地址（&x），scanf 需要把结果写回变量
%s 有风险 输入无宽度限制，容易缓冲区溢出，建议 %19s 限宽
空白字符 输入时空白（空格/Tab/换行）默认被跳过，%c 除外
正负号 %d 支持正负号，%u 不支持负号
返回值 返回成功匹配的个数，务必检查

I/O 缓冲

对于写文件系统调用 write() 与磁盘操作并不是同步的，write() 函数并不会等待数据真正写入到磁盘之后再返回。如果在此期间，其它进程调用 read() 函数读取该文件的这几个字节数据，那么内核将自动从缓冲区中读取这几个字节数据返回给应用程序。

对于读文件而言亦是如此：内核会从磁盘设备中读取文件的数据并存储到内核的缓冲区中，当调用 read() 函数读取数据时，read() 调用将从内核缓冲区中读取数据，直至把缓冲区中的数据读完，这时，内核会将文件的下一段内容读入到内核缓冲区中进行缓存。

刷新文件 I/O 的内核缓冲区

函数 刷新范围 刷新内容 成功返回 失败返回
sync() 整个系统 所有文件的数据 + 元数据 无（void） —
syncfs() 单个文件系统 fd 所属文件系统的数据 + 元数据 0 -1
fsync() 单个文件 fd 所指文件的数据 + 元数据 0 -1
fdatasync() 单个文件 fd 所指文件的数据（不含元数据） 0 -1

sync()

作用:: 将所有文件 I/O 内核缓冲区中的文件内容数据和元数据全部更新到磁盘设备中

用法：

注意事项：

  1. Linux 系统中调用 sync() 函数仅在所有数据已经写入到磁盘设备之后才会返回
  2. 影响范围是整个系统所有文件，开销大，一般在关机前或定期执行
  3. 应用层程序中很少直接调用，多由系统工具（如 sync 命令）使用

syncfs()

作用:: 将参数 fd 所指文件所属文件系统的所有内核缓冲数据（数据和元数据）刷新到磁盘

用法：

  • fd：属于目标文件系统的任意一个打开文件的文件描述符

注意事项：

  1. 与 sync() 的区别：只同步 fd 所在的一个文件系统，而不是整个系统
  2. Linux 2.6.39 之后提供，glibc 2.14 之后可用

fsync()

作用:: 将参数 fd 所指文件的内容数据和元数据写入磁盘

用法：

  • fd：目标文件的文件描述符

注意事项：

  1. 只有在对磁盘设备的写入操作完成之后，fsync() 函数才会返回——确保数据真正落盘
  2. 同时刷新内容数据 + 元数据（元数据如文件大小、修改时间、权限等）
  3. 典型场景：数据库、日志系统在关键写入后调用 fsync，防止断电丢数据

fdatasync()

作用:: 仅将参数 fd 所指文件的内容数据写入磁盘，并不包括文件的元数据

用法：

  • fd：目标文件的文件描述符

注意事项：

  1. 与 fsync 相比少刷元数据，性能更好（元数据刷盘也是磁盘 I/O）
  2. 如果后续写操作没有修改文件大小等元数据，用 fdatasync 就足够了
  3. 需要元数据也落盘（如刚创建文件、修改了文件大小）时，应使用 fsync

O_DSYNC 与 O_SYNC 标志

调用 open() 函数时指定一些标志也可以影响到文件 I/O 内核缓冲：

标志 效果 等价操作
O_DSYNC 每个 write() 调用后自动同步文件内容数据 相当于每次 write 后调用 fdatasync()
O_SYNC 每个 write() 调用后自动同步文件内容数据和元数据 相当于每次 write 后调用 fsync()
  • O_DSYNC 标志：其效果类似于在每个 write() 调用之后调用 fdatasync() 函数进行数据同步
  • O_SYNC 标志：使得每个 write() 调用都会自动将文件内容数据和元数据刷新到磁盘设备中，其效果类似于在每个 write() 调用之后调用 fsync() 函数进行数据同步

💡 与手动 fsync 的区别：O_SYNC 是「每次 write 都同步」，适合小数据量高频写入；手动 fsync 是「攒一批再同步」，性能更好，适合批量写入。

直接 I/O（O_DIRECT）

在执行文件 I/O 操作时绕过内核缓冲区，从用户空间直接将数据传递到文件或磁盘设备，把这种操作也称为直接 I/O。

例如，某应用程序的作用是测试磁盘设备的读写速率，那么在这种应用场景下，就需要保证 read/write 操作是直接访问磁盘设备，而不经过内核缓冲。使用直接 I/O 可以在 open() 函数打开文件时指定 O_DIRECT 标志：

在执行直接 I/O 时，必须要遵守以下三个对齐限制要求：

  1. 应用程序中用于存放数据的缓冲区，其内存起始地址必须以块大小的整数倍进行对齐
  2. 写文件时，文件的位置偏移量必须是块大小的整数倍
  3. 写入到文件的数据大小必须是块大小的整数倍

注意事项：

  1. 需要进行宏定义 _GNU_SOURCE 才能在 open() 函数中使用 O_DIRECT 标志
  2. 存放数据的缓冲区需要使其起始地址以 4096 字节进行对齐，使用 __attribute__((aligned(4096))) 声明
  3. 块大小通常为 4096 字节（可通过 fdisk -l 或 stat 查看实际块大小）

⚠️ 直接 I/O 一般只用于磁盘测试、数据库等特殊场景，普通应用不要使用——它失去了 page cache 的缓存加速，性能反而可能更差。

stdio 缓冲

标准 I/O 的 stdio 缓冲是用户空间的缓冲区。当应用程序中通过标准 I/O 操作磁盘文件时，为了减少调用系统调用的次数，标准 I/O 函数会将用户写入或读取文件的数据缓存在 stdio 缓冲区，然后再一次性将 stdio 缓冲区中缓存的数据通过调用系统调用 I/O（文件 I/O）写入到文件 I/O 内核缓冲区或者拷贝到应用程序的 buf 中。

C 语言标准 I/O 提供了三种缓冲模式：

模式 宏 说明 默认使用场景
全缓冲 _IOFBF 缓冲区满时才刷新 磁盘文件
行缓冲 _IOLBF 遇到换行符 '' 时刷新 终端设备（stdin/stdout）
无缓冲 _IONBF 每次读写直接系统调用 stderr

对于终端设备默认采用的就是行缓冲模式，譬如标准输入和标准输出：printf() 输出的字符串写入到了标准输出的 stdio 缓冲区中，只有输出换行符时才会将这一行数据刷入到内核缓冲区。调用 scanf() 函数进行阻塞时，用户通过键盘输入数据，只有在按下回车键（换行符键）时程序才会接着往下执行。

关于刷新时机：

  • 调用 fflush() 库函数可强制刷新指定文件的 stdio 缓冲区
  • 调用 fclose() 关闭文件时会自动刷新文件的 stdio 缓冲区
  • 程序退出时会自动刷新 stdio 缓冲区

setbuf()、setbuffer()、setvbuf()

作用:: 设置文件流的 stdio 缓冲区及其模式

用法：

  • stream：目标文件流
  • buf：用户提供的缓冲区（传 NULL 则让 stdio 自动分配）
  • size：缓冲区大小（setbuffer、setvbuf 使用）
  • mode：缓冲模式，取 _IOFBF（全缓冲）/ _IOLBF（行缓冲）/ _IONBF（无缓冲）

注意事项：

  1. 必须在打开文件之后、任何读写操作之前设置，否则无效
  2. 三种设置方式的关系：setbuf(fp, buf) 等价于 setvbuf(fp, buf, buf ? _IOFBF : _IONBF, BUFSIZ)；setbuffer(fp, buf, size) 是 BSD 扩展，等价于指定大小的 setbuf
  3. 如果自己提供 buf，必须保证 buf 在 fclose 之前一直有效——不能用栈上的局部数组然后在函数返回后继续使用
  4. 一旦对文件流执行过读写操作，再设置缓冲区将导致未定义行为

fflush()

作用:: 强制刷新指定文件的 stdio 输出缓冲区

用法：

  • stream：目标文件流；传 NULL 表示刷新所有打开的输出流

注意事项：

  1. fflush() 只是把 stdio 用户空间缓冲区中的数据交给内核（write 系统调用），并不保证数据落盘——真正落盘需要 fsync()/fdatasync()
  2. 对输入流调用 fflush 是未定义行为（个别实现用于丢弃缓冲）
  3. 常见场景：调试信息想立即看到、程序马上要 sleep/等待输入、日志需要及时输出时

文件描述符与 FILE 指针互转

函数 转换方向 成功返回 失败返回
fileno() FILE 指针 → 文件描述符 文件描述符 fd -1
fdopen() 文件描述符 → FILE 指针 FILE * NULL

fileno() — FILE * 转 fd

作用:: 将标准 I/O 中使用的 FILE 指针转换为文件 I/O 中所使用的文件描述符

用法：

  • stream：FILE 指针

注意事项：

  1. 转换之后两种方式可以混用，但注意不要绕过 stdio 缓冲直接 read/write，否则可能读到旧数据或丢数据
  2. 获取到 fd 后就可以使用 fsync()、fstat() 等只能操作 fd 的系统调用
  3. 典型场景：fileno(stdout) 得到 1，用于 dprintf 输出

fdopen() — fd 转 FILE *

作用:: 将文件描述符转换为 FILE 指针，从而可以使用标准 I/O 库函数操作它

用法：

  • fd：文件描述符（open/socket/pipe 的返回值）
  • mode：打开模式，必须与 fd 原本的打开方式兼容（如 fd 是 O_RDONLY 打开的，mode 只能用 "r"）

注意事项：

  1. fdopen() 并不会复制 fd，转换后二者指向同一个文件表项——调用 fclose() 关闭 FILE 流时，底层的 fd 也会被关闭
  2. 如果还想继续使用 fd，先用 dup() 复制一份再 fdopen
  3. 典型场景：把 socket/管道 的 fd 包装成 FILE*，就能用 fprintf/fscanf 等标准 I/O 函数读写
