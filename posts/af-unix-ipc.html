Unix域套接字（AF_UNIX）实现进程间双向通信

发表于2026-08-28|更新于2026-08-28|Linux
|字数总计:6.5k|阅读时长:28分钟|阅读量:

总结

小结:: Unix 域套接字（AF_UNIX）是同一台主机上进程间通信（IPC）的高效方式：不走网络协议栈，内核直接拷贝数据，性能优于 TCP 回环（localhost）。本文基于一个 AF_UNIX + SOCK_STREAM 的完整示例项目（master 服务器 / servant 客户端）复盘整理：master 用「accept 线程 + listen 线程」双线程模型配合 poll 多路复用同时服务多个客户端；servant 从标准输入读消息发给 master，master 回显。重点掌握：服务端五步流程（socket → bind → listen → accept → read/write）、poll 的使用流程、poll 阻塞下收到信号的优雅退出（超时轮询 + 先关 fd 再 join）、以及 poll 与 epoll 的本质区别。

  1. AF_UNIX 用「文件路径」当地址，仅限本机通信，性能优于 TCP 回环
  2. 服务端流程：unlink → socket → bind → listen → poll/accept → read/write
  3. 客户端流程：socket → connect → read/write
  4. 双线程模型：accept 线程负责「接客」，listen 线程负责「读写」，互不阻塞
  5. 优雅退出三铁律：poll 带超时、先关 fd 再 join、信号处理器只翻 atomic 标志
  6. poll 与 epoll：poll 跨平台 O(n) 遍历，epoll Linux 专属 O(1) 就绪通知

Unix 域套接字是什么

定义

Unix 域套接字（Unix Domain Socket）是同一台主机内进程间通信的套接字机制。它和 TCP 套接字使用几乎相同的 API（socket / bind / listen / accept / connect / read / write），只是地址族不同：

对比项 AF_INET（网络套接字） AF_UNIX（域套接字）
地址标识 IP + 端口 文件系统路径（如 /tmp/mytest.sock）
通信范围 跨主机 仅本机
数据路径 经过 TCP/IP 协议栈（封装/解封装、校验） 内核直接拷贝，不经过协议栈
性能 有协议开销 更快（本机 IPC 首选）
断开表现 对端崩溃靠 TCP 超时检测 对端进程崩溃时 fd 立即出现 POLLHUP

💡 一句话记忆：AF_UNIX = 用「文件路径」当地址的 socket。TCP 是「打电话」，Unix Socket 是「递纸条」——都在一个屋里（同一台机器），不用走电话线（协议栈）。

关键特性

  1. 地址是文件：bind 后会在文件系统生成一个 socket 文件（ls -l 显示 srwxr-xr-x），connect 就是连接这个文件。
  2. 需要手动清理：进程退出后 socket 文件不会自动删除，下次 bind 会报 EADDRINUSE → 必须先 unlink。
  3. 流式（STREAM）与数据报（DGRAM）：SOCK_STREAM 无消息边界（同 TCP）；SOCK_DGRAM 保留消息边界（同 UDP）。
  4. 抽象命名空间（进阶）：sun_path[0] = '\0' 时不占文件系统，进程退出自动消失，无需 unlink。

项目架构总览

  • master：服务器。socket → bind → listen 后开两个线程：
    • accept_thread：只负责 poll 监听 fd，有新连接就 accept，把客户端 fd 加入数组；
    • listen_thread：poll 所有客户端 fd，可读就 read 并原样回显（echo）。
  • servant：客户端。socket → connect 后循环：从标准输入读一行 → write 给 master → read 等回显。

💡 双线程模型的意义：accept 和业务读写分离。如果单线程里 accept 阻塞，新连接来的时候可能处理不了已有客户端的数据；拆两个线程各自 poll，互不阻塞。

核心函数详解

socket() — 创建套接字

参数 含义 本项目取值
domain 地址族（协议族） AF_UNIX（域套接字）
type 套接字类型 SOCK_STREAM（流式，可靠双向）
protocol 具体协议 0（由前两个参数自动决定）
  • 返回：成功返回文件描述符（fd），失败返回 -1。
  • SOCK_STREAM：有序、可靠、双向、无消息边界（适合本项目 echo）。
  • SOCK_DGRAM：保留消息边界、不可靠、效率高。

bind() — 绑定地址

  • 作用：把 socket 和一个本地地址绑定。AF_UNIX 下就是「把 socket 文件创建到指定路径」。
  • addr：struct sockaddr_un 的指针（需要强转 (struct sockaddr*)）。
  • 常见错误 EADDRINUSE：路径已被占用 → 绑定前先 unlink。

listen() — 进入监听状态

  • 作用：把 socket 变为被动监听（服务器专属），等待客户端连接。
  • backlog：等待 accept 的连接队列长度。本项目 listen(sockfd_, 5) 表示最多 5 个连接排队，第 6 个会连接失败。

accept() — 接受连接

  • 作用：从队列中取出一个连接，返回一个新的 fd（专门和这个客户端通信）。

  • 注意：sockfd（监听 fd）只负责接客，不负责传数据；传数据用 accept 返回的新 fd。

  • 阻塞模式下，没有连接时 accept 会阻塞 → 所以要先 poll 确认可读再 accept。

  • ⚠️ 优先级陷阱：if (fd = accept(...) < 0) 会先比较后赋值（fd 变成 0/1）！必须分开写：

connect() — 发起连接（客户端）

  • 作用：客户端向服务器地址发起连接请求。
  • AF_UNIX 下连接失败常见原因：路径没对上（比如 strncpy 少拷了字符）、服务器没启动、socket 文件不存在。
  • 失败返回 -1，用 strerror(errno) 打印具体原因。

read() / write() — 数据收发

read 返回值语义（重要！）：

返回值 含义
> 0 读到 n 个字节
== 0 对端关闭连接（不是"读完了"！）
< 0 出错，看 errno（EINTR 被信号打断，重试；EAGAIN 非阻塞下无数据）

write 返回值语义：

返回值 含义
> 0 写了 n 个字节（可能没写完！要循环写）
== 0 什么都没写（一般要重试或视为异常）
< 0 出错，看 errno

⚠️ 流式 socket 没有消息边界：read == 0 不是"这包读完了"，而是"对端不写了（关闭）"。一次 read 也可能只读到半条消息。业务上的"一帧"要自己定协议（定长 / 长度前缀 / \n 分隔）。这一条对 AF_UNIX 和 TCP 完全一样。

⚠️ write 可能写不完：发送缓冲区满时只写入部分字节，必须循环写直到 total_bytes == 0（本项目 writer_f 就是标准写法）。

shutdown() / close() — 断开连接

函数 区别
close 释放 fd，彻底关闭（读写都不能用）
shutdown 优雅地半关闭：只关读 / 只关写 / 全关

shutdown 的 how 参数：

参数 含义
SHUT_RD 关闭读方向（不能再 read）
SHUT_WR 关闭写方向（不能再 write，对端 read 会返回 0）
SHUT_RDWR 读写都关（本项目用它唤醒 poll）

💡 本项目 close_pipe 里先 shutdown(sockfd_, SHUT_RDWR) 再 close(sockfd_)：shutdown 会立刻让阻塞在 poll/read 上的线程醒来（fd 事件变为可读/错误），这是唤醒阻塞线程的关键一步。

unlink() — 删除 socket 文件

  • 作用：删除文件系统里的 socket 文件。
  • 为什么必须删：bind 失败返回 EADDRINUSE 只发生在 socket 文件已存在时；进程崩溃/退出后文件残留，下次启动必须先 unlink。
  • 注意：unlink 只是删文件名，不关闭已打开的 fd。

signal() — 注册信号处理

  • 作用：注册信号处理函数。本项目注册 SIGINT（Ctrl+C）：

  • ⚠️ 信号处理器必须 async-signal-safe：里面只能做原子操作（atomic 标志、write 等），绝不能 join 线程、cout、malloc、加锁——否则可能死锁或崩溃。

关键结构体与系统参数

struct sockaddr_un — AF_UNIX 地址

字段 说明
sun_family 必须填 AF_UNIX
sun_path 路径字符串，最大 107 字符 + '\0'

⚠️ 路径长度陷阱：strncpy(addr.sun_path, path, sizeof(addr.sun_path) - 1) —— 必须用 sizeof - 1（留 '\0'），而且不能用 strlen(path) - 1（会少拷最后一个字符，连接永远失败）。填完建议 sun_path[sizeof-1] = '\0' 兜底。

struct pollfd — poll 的监视单元

poll 事件标志

标志 events 可设？ revents 可能 含义
POLLIN ✅ ✅ 可读（有数据 / 对端关闭 / 有新连接）
POLLOUT ✅ ✅ 可写（发送缓冲区有空间）
POLLERR ❌ ✅ 发生错误（如对端 RST）
POLLHUP ❌ ✅ 挂起（对端关闭了连接）
POLLNVAL ❌ ✅ fd 无效（已被 close）

💡 POLLIN 是"有东西可读"的总开关：新连接（监听 fd）、数据、对端关闭（read 返回 0）都会置位。而 POLLERR / POLLHUP / POLLNVAL 只能出现在 revents（内核通知你），不能自己设置。

本项目退出时靠 POLLHUP/POLLERR 兜底：if (poll_accept_.revents & (POLLERR | POLLHUP | POLLNVAL)) break; —— fd 被 close_pipe 关掉后，poll 会立刻带着错误事件返回。

常见 errno

errno 触发场景 处理方式
EINTR 阻塞系统调用（poll/read/write）被信号打断 continue 重试（不是错误！）
EAGAIN / EWOULDBLOCK 非阻塞 fd 缓冲区空/满 本轮结束，等下次事件
EBADF fd 无效（已被 close） 项目里用它判断"fd 已被 close_pipe 关掉"，直接退出
EADDRINUSE bind 的路径已被占用 先 unlink 再 bind

poll 函数的使用流程

函数原型

参数 含义
fds pollfd 数组（监视多个 fd）
nfds 数组元素个数
timeout 超时（毫秒）：-1 无限等待；0 立即返回；>0 等 N 毫秒

返回值：

返回值 含义
> 0 有 revents != 0 的 fd 个数
== 0 超时，没有事件
< 0 出错（errno == EINTR 是被信号打断，重试）

完整使用流程

本项目 poll 的三个使用要点

  1. 带超时（200ms）而不是 -1：超时醒来检查 is_running_，是优雅退出的第一道保险。
  2. poll 是电平触发（LT）：有数据就一直通知，读一次没读完，下次 poll 还会通知 → 安全简单，不会漏事件。
  3. 每次 poll 前不用重建数组：events 不会像 select 的 fd_set 那样被内核改写（只有 revents 会变），所以数组可以复用。

poll 阻塞时收到终止信号，如何安全退出？

问题在哪

  • 如果 poll 用 -1 无限阻塞，Ctrl+C 来了，信号处理器把 is_running_ 置 false —— 但 poll 还堵着不返回，循环根本检查不到标志 → 主线程 join 子线程时永远等不到 → 程序卡死在退出流程。
  • 就算信号把 poll 打断返回 EINTR，如果你 continue 了，poll 又会立刻重新阻塞。

正确方案：两路退出

第一路：带超时的 poll（主动检查）

第二路：关 fd 唤醒（被动唤醒）

close_pipe 里先关 fd 再 join：

完整退出时序（本项目）

三个铁律

# 铁律 原因
1 poll 永远带超时（如 200ms），不要 -1 让循环有机会检查退出标志
2 先关 fd，再 join 关 fd 唤醒阻塞线程，join 才不会死等（顺序反了 = 死锁）
3 信号处理器只翻转 atomic 标志 处理器里 join/cout/malloc 都可能死锁；标志必须用 std::atomic（信号上下文安全）

💡 进阶方案（了解即可）：signalfd + poll 统一监视信号、或 self-pipe trick（信号处理器里 write 一个管道字节唤醒 poll）。本项目用「带超时 + 关 fd」已经足够。

poll 与 epoll 的区别

核心对比

对比项 poll epoll
平台 POSIX 标准，可移植（Unix/Linux/macOS） Linux 专属
内核机制 每次调用把整个 fd 数组拷进内核，内核全量遍历所有 fd epoll_ctl 注册时拷入（红黑树管理），epoll_wait 只返回就绪的 fd（就绪链表）
时间复杂度 每次 O(n) 遍历全部 fd 注册 O(1)，等待 O(1)（只取就绪事件）
fd 数量上限 无硬性上限（受进程 fd 限制） 无上限，支持海量连接（C10K）
触发模式 只有电平触发（LT） LT + 边缘触发（ET）（EPOLLET）
编程模型 每次调用后自己遍历数组找 revents epoll_wait 直接给你就绪事件数组，只处理就绪的
API 一个 poll() 三个：epoll_create / epoll_ctl / epoll_wait
适用场景 fd 数量少、追求跨平台、代码简单 高并发、大量空闲连接、性能敏感

直观理解

类比：poll 像点名（每天把全班 50 人挨个喊一遍，看谁举手）；epoll 像挂失（跟老师登记好，谁有事老师主动通知你，不用挨个问）。

触发模式差异

触发模式 poll epoll
LT（水平触发） ✅ 唯一模式 ✅ 默认模式
ET（边缘触发） ❌ 无 ✅ EPOLLET 可选
  • poll 本质是 LT：缓冲区有数据就一直通知 → 读一次没读完也不怕漏。
  • epoll 的 ET 只在状态变化时通知一次 → 必须配非阻塞 fd + 循环读到 EAGAIN，否则数据永久丢失。

什么时候用哪个

场景 推荐
几十个连接、要跨平台、代码简单 poll（本项目场景）
上千上万连接、高并发服务器 epoll
需要边缘触发精打细算性能 epoll + EPOLLET + 非阻塞

编译与运行

踩坑清单（含 TCP 通用部分）

⚠️ 这一节是实战总结。凡是「流式 socket 通用」的坑，对 AF_UNIX 和 TCP 一样成立——因为两者都是 SOCK_STREAM 字节流，读写的语义完全相同。写 TCP 程序时同样要小心。

流式 socket 读写（AF_UNIX 与 TCP 通用）

  1. ❌ while (read != 0) 想"读完全部数据" → read == 0 是对端关闭，不是"包读完了"。流式没有消息边界，TCP 也一样。
  2. ✅ POLLIN 后读一次立刻处理/回写；要抽干缓冲区必须非阻塞 fd 循环读到 EAGAIN。
  3. ✅ 业务消息边界自己定协议：定长 / 长度前缀 / \n。
  4. ✅ write 要循环写（缓冲区满只写一部分），TCP 下同样适用。

退出与线程（AF_UNIX 与 TCP 通用）

  1. ❌ poll(fds, n, -1) 无限等待 → 信号来了循环检查不到标志。
  2. ❌ close_pipe 里先 join 再 close(fd) → 子线程堵在 poll 里，join 死等 = 死锁。
  3. ✅ 收尾顺序：置标志 → shutdown/close fd（唤醒）→ join。
  4. ✅ 信号处理器只改 atomic 标志，不做 join / cout / 复杂逻辑。

参数与语法小坑（与协议无关，纯 C/C++ 层面）

  1. ❌ strncpy(path, strlen(path) - 1) → 少拷最后一个字符 → connect 永远失败。
  2. ❌ if (fd = accept(...) < 0) → 先比较后赋值，fd 变成 0/1 → 先赋值再比较。
  3. ❌ if (write(...) < 0); { ... } → 分号使 if 变空语句，后面块无条件执行。
  4. ❌ std::copy 到 clear() 后的空容器 → copy 不扩容，size 仍为 0 → 用 assign / append。
  5. ❌ lambda 里 return -1 和 return size() 混用 → int/size_t 推导冲突 → 显式 -> int。
  6. ❌ runtime_error("...%d", fd) → C++ 没有 printf 接口 → 用 to_string 拼接。
  7. ❌ 单例对象手动 ~T() → 生命周期由 static 管理 → 公开 close_pipe() 即可。

Unix Socket 特有（AF_UNIX 专属）

  1. ✅ bind 前先 unlink 旧文件，否则 EADDRINUSE。
  2. ✅ sun_path 用 sizeof - 1 长度拷贝，留 '\0'。
  3. ✅ 服务端和客户端的 sun_family / type 必须一致。
  4. ✅ 对端进程崩溃时 fd 会收到 POLLHUP，read 返回 0 —— 记得清理。

一句话总结

  1. AF_UNIX：用文件路径当地址的 socket，本机 IPC 性能之王。
  2. 服务端流程：unlink → socket → bind → listen → poll/accept → read/write；客户端：socket → connect → read/write。
  3. poll：带超时调用，POLLIN 读一次处理一次，EINTR 重试，POLLERR/HUP/NVAL 清理。
  4. 安全退出：poll 带超时 + 关 fd 唤醒 + 先关再 join，信号处理器只翻 atomic 标志。
  5. poll vs epoll：poll 跨平台 O(n) 遍历，epoll Linux 专属 O(1) 就绪通知；连接少用 poll，高并发用 epoll。
