第15章 套接字与标准 I/O

发表于2026-07-15|更新于2026-07-16|TCP-IP网络编程
|字数总计:2k|阅读时长:8分钟|阅读量:

总结

小结:: 第15章介绍如何将套接字（file descriptor）与标准 I/O 函数库结合使用。标准 I/O 带缓冲，能减少系统调用次数从而提升性能，但套接字的半关闭（shutdown）无法直接用于 FILE* 对象。核心函数为 fdopen()（fd → FILE) 和 fileno()（FILE → fd）。本章还讨论了标准 I/O 的三种缓冲模式及其对网络通信的影响。

标准 I/O 函数 vs 系统 I/O 函数

系统 I/O 函数（System I/O）

系统 I/O 是操作系统直接提供的底层 I/O 接口，也称为「低级 I/O」（Low-Level I/O）。

函数 说明
open() / close() 打开/关闭文件或套接字
read() / write() 读写数据
lseek() 移动文件指针

标准 I/O 函数（Standard I/O）

标准 I/O 是 C 语言标准库提供的高级 I/O 接口，内部封装了系统 I/O。

函数 说明
fopen() / fclose() 打开/关闭文件流
fread() / fwrite() 读写数据块
fgets() / fputs() 字符串读写
fprintf() / fscanf() 格式化读写
fflush() 刷新缓冲区

标准 I/O 的优点 ✅

  1. 跨平台性好 — ANSI C 标准，几乎所有平台都支持
  2. 带缓冲 — 内部维护 I/O 缓冲区，减少系统调用次数 → 性能提升
  3. 方便易用 — 提供格式化 I/O、字符串 I/O 等高层接口

为什么缓冲能提升性能？ 每次系统调用（read/write）都会触发用户态↔︎内核态切换，开销很大。标准 I/O 将多次小数据写入合并为一次大块写入，大幅减少上下文切换。

标准 I/O 的缺点 ❌

  1. 不易于双向通信 — 套接字是双向的，但标准 I/O 的缓冲策略可能导致数据无法及时发送/接收
  2. 可能多次调用 fflush — 需要手动刷新缓冲区才能确保数据通过套接字发送
  3. 必须用 FILE* 方式打开 — 套接字本身是 fd，需要转换后才能使用标准 I/O

使用标准 I/O 函数

fdopen() — 将文件描述符转换为 FILE*

  • fd：文件描述符（包括套接字描述符）
  • mode：打开模式，与 fopen() 相同（"r", "w", "r+" 等）
  • 返回值：成功返回 FILE* 指针，失败返回 NULL

⚠️ 注意：fdopen() 不会复制文件描述符，而是共享同一个底层描述符。关闭 FILE* 也会关闭对应的 fd。

fileno() — 从 FILE* 获取文件描述符

  • stream：FILE* 指针
  • 返回值：成功返回文件描述符，失败返回 -1

标准 I/O 的缓冲问题

三种缓冲模式

标准 I/O 提供三种缓冲策略：

模式 说明 典型场景
全缓冲
_IOFBF		 缓冲区填满后才进行实际 I/O 操作 普通磁盘文件（默认）
行缓冲
_IOLBF		 遇到换行符 \n 时刷新缓冲区 终端交互（stdin/stdout）
无缓冲
_IONBF		 不缓冲，每次 I/O 立即执行 stderr（默认）

套接字使用标准 I/O 时的 数据传输延迟问题

当套接字通过 fdopen() 转换为 FILE* 后，默认使用全缓冲模式（因为底层不是终端设备）。这意味着：

后果：客户端发送数据后，服务器没有收到；服务器回复后，客户端也没有收到。双方都在等待对方，造成死锁。

解决方案：合理使用 fflush

设置缓冲模式：setvbuf()

  • stream：目标 FILE* 指针
  • buf：用户自定义缓冲区（NULL 则自动分配）
  • mode：_IOFBF（全缓冲）、_IOLBF（行缓冲）、_IONBF（无缓冲）
  • size：缓冲区大小

⚠️ 但行缓冲对套接字并不总是可靠，因为网络消息不一定以换行符结尾。最保险的做法仍然是 显式调用 fflush()。

半关闭与标准 I/O 的问题

⚠️ shutdown 不能用于 FILE*

使用标准 I/O 后，套接字的「半关闭」功能不能直接使用，因为 shutdown() 需要文件描述符，而 FILE* 无法直接传入。

本章总结 🎯

核心概念 关键函数/说明
fd → FILE* fdopen(fd, mode)
FILE* → fd fileno(fp)
缓冲模式 _IOFBF(全缓冲)、_IOLBF(行缓冲)、_IONBF(无缓冲)
强制刷新 fflush(fp)
设置缓冲 setvbuf(fp, buf, mode, size)
半关闭 需用 fileno() 获取 fd 后调用 shutdown()

一句话总结：fdopen() 让套接字用上标准 I/O 的便利与性能，但必须时刻注意缓冲问题和半关闭限制——fflush 是你的好习惯，fileno + shutdown 是半关闭的关键。
